# 단계별 내용 검토

체크 도구는 파일·ID·상태·참조·검토 이후 변경을 검사한다. 아래 내용은 에이전트가 실제 자료와 결과를 읽어 검토한다. 미확정 사항은 질문과 가정으로 표시한다. 문서 길이·표 개수로 완료 여부를 판단하지 않는다.

| 단계 | 검토할 내용과 실제 근거 |
| --- | --- |
| discovery | 고객/사용자 문제, 목표, 원문 요구사항, 누락·충돌, 사업 가능성, 진행 판단에 필요한 질문 |
| proposal | 요구별 제안 대응, 범위·제외·가정, 수행 방법, 일정·공수 산식, 위험, 제안 조건과 계약 조건의 구분 |
| kickoff | 확정 범위와 계약/투자 결정, 책임자, 일정·의존성, 검토·소통 방법, 변경·수용 절차 |
| planning | 사용자 흐름·화면·데이터·권한·예외, 수용기준, API/구성/배포 설계, 기술 선택 이유, REQ→설계 연결 |
| design | 화면과 상태(정상·로딩·빈 화면·오류·권한 없음), 반응형, 디자인 토큰·컴포넌트, 접근성, Figma 버전·노드 |
| publishing | 실제 화면·컴포넌트, 주요 크기와 브라우저, 키보드·레이블, 로딩·오류, 화면 검증 이미지/결과 |
| implementation | 수용기준별 실제 코드, 입력 검증·접근권한, 실패 경로, 코드 리뷰, REQ→파일·커밋 연결 |
| verification | 요구별 테스트, 실행 환경·명령·날짜·결과, 실패·미실행·수정·회귀, REQ→실제 테스트 증거 연결 |
| release | 커밋·버전·릴리스 노트, 환경·설정·비밀정보 관리, 배포 결과·상태 점검, 실패 시 복구 방법과 확인 결과 |
| handover | 요구→납품 목록 양방향 연결, 인수 결과, 소스·라이선스·매뉴얼·권한 이전, 미결함·제한·지원 합의 |
| maintenance | INC/CR, 재현·원인·영향·우선순위·담당자, 회귀·배포·복구, 합의된 지원 범위와 운영 점검 |

UI가 없는 API 사업 등은 적용하지 않는 산출물의 사유를 남기고 실제 검토를 기록한다. 실행을 못 한 검증은 미실행으로 보고한다. 사업·계약상의 필수 조건은 일반 기본형보다 우선한다.
