# 이음 · 프로젝트 스타트팩 에이전트

사용자는 짧은 한국어 요청과 자료를 전달한다. 에이전트가 필요한 절차·지침·양식·역할을 선택하고 실제 작업을 수행한다. 사용자가 명령어·역할 ID·셸·JSON/CSV 편집을 외울 필요가 없게 한다.

## 기존 엔진과 연결

먼저 [기존 실행 스킬](../project-lifecycle/SKILL.md)을 읽고 해당 시작·기록·검토·인수인계 규약을 그대로 적용한다. 이 스킬의 두 단계 위가 플러그인 루트다. 도구는 [starter.py](../../tools/starter.py), 역할 도구는 [role_agents.py](../../tools/role_agents.py)다. 설치 경로를 추측하거나 플러그인 캐시를 고객 작업 공간으로 쓰지 않는다.

`$ieum`은 Codex 스킬 호출이다. Claude Code는 프로젝트별 짧은 별칭 설정 후 `/ieum`을 사용한다. 원래 플러그인 호출은 `/project-lifecycle-agent:ieum`이며 설치·별칭 진단용으로 유지한다. “이음 기획해줘” 같은 표현은 자연어 요청이며 `/이음`이 모든 호스트에서 등록된 명령이라고 안내하지 않는다. 기존 호출은 계속 유효하다.

## 요청을 작업으로 연결

| 사용자 표현 | 기본 역할과 행동 |
| --- | --- |
| 이음 도움말 / 역할 보여줘 | 가능한 요청 예시·역할 이름·현재 프로젝트의 다음 행동 안내. 프로젝트 생성 불필요 |
| 이음 시작 / 이어서 / 현황 | 기존 엔진으로 discover·inspect 후 새 프로젝트 또는 실제 현재 단계에서 재개 |
| 이음 제안 | proposal-strategist → proposal-producer. RFP 평가·템플릿 원본·실제 파일·렌더링 검수 연결 |
| 이음 기획 | po → spec → ia. 요청 범위의 PRD·정책·흐름을 구체화 |
| 이음 설계 | architect → database. 필요한 API·데이터·인프라 계약 조율 |
| 이음 디자인 | design-system → ui·ux-writer. 기존 브랜드·토큰·화면 상태부터 확인 |
| 이음 개발 | architect의 계약과 실제 저장소 확인 후 backend·frontend·devops 중 필요한 역할만 선택 |
| 이음 검토 | qa·security·reviewer 중 요청과 위험에 맞는 검토. 코드 수정은 소유 개발자에게 전달 |
| 이음 배포 / 인수인계 | devops·technical-writer. 실제 권한·실행·복구·매뉴얼 근거 확인 |
| 이음 역할 [이름]으로 ... | 역할 도구 show로 해당 계약만 읽고 직접 수행 또는 허용된 위임 |

정확한 문자열 명령 파서가 아니다. 예를 들어 “기획만” 요청에 제안·개발까지 자동 진행하지 않는다. 현재 단계의 초안 작성은 가능하지만 선행 승인·단계 전이를 생략하지 않는다.

## 역할 선택과 실행

역할은 [roles.json](references/roles.json)의 18개 계약으로 정의한다. 전체 상세를 매번 읽지 말고 역할 도구 `list`, `show <역할 ID 또는 한국어 별칭>`로 필요한 입력·산출물·검증·책임 경계만 읽는다. 역할 목록은 주석이 아닌 실제 호스트 정의와 같은 원천에서 생성한다.

[공통 협업 규약](references/COLLABORATION.md)과 [자동 실행 규약](references/AUTO-EXECUTION.md)을 적용한다. **요청에 맞는 역할 선택과 필요한 하위 에이전트 실행은 기본 동작이다.** 사용자가 “팀으로”, “병렬로”라고 말하거나 역할을 지명할 필요가 없다. 이 스킬은 복합 작업의 자동 위임을 명시적으로 요청하는 적용 지침이다. 사용자의 작업 요청 자체가 필요한 역할 수행의 범위이며, 역할 실행 전에 별도의 팀 승인 질문을 하지 않는다.

단순 질문·도움말·현황 조회·작은 단일 파일 수정은 주 에이전트가 직접 처리한다. 구현과 독립 검토가 함께 필요하거나, 여러 전문 영역·서로 다른 산출물이 필요한 작업은 역할 계약으로 나누고 실제 호스트 하위 에이전트를 자동 실행한다. 사용자가 단일 에이전트 수행을 지정하면 존중한다. 실행할 수 없는 호스트에서는 직접 역할 모드로 수행하고 제한·미실행 역할을 보고한다. 독립 입력과 서로 다른 담당 경로가 있는 작업만 병렬 처리하며, 그 외는 선행 결과를 받은 뒤 순차 위임한다. 호스트 동시 실행 한도 안에서 필요한 최소 작업자를 사용하고 재귀 위임하지 않는다.

위임 전 실제 프로젝트 루트·REQ/TASK·입력 파일·기준 버전·담당 경로·출력·수용 기준을 작업 묶음으로 전달한다. 복수 작업은 기존 run-create/run-result/run-resume의 실행·의존성·해시·revision 규약으로 기록한다. 같은 원인의 수정·재검토가 두 번 연속 실패하면 영향받는 작업을 blocked로 정리하고 근거·해결 조건을 반환한다. 독립 작업은 계속하며 사용자 결정이나 외부 상태 변경 없이 같은 실패를 반복하지 않는다. 원장과 HANDOFF는 주 에이전트가 단일 기록자다. 역할 결과를 실제 파일·테스트로 검증하고 요청한 결과까지 통합한다. 역할 계획을 나열한 것만으로 작업 완료라고 하지 않는다.

## 호스트별 연결

- Claude Code 짧은 명령: 프로젝트 시작·연결 또는 짧은 명령 설정 요청 시 실제 고객 프로젝트에서 역할 도구 `claude-preview <프로젝트>` 결과를 JSON 파일에 저장한 뒤 `claude-install <프로젝트> --file <미리보기 파일>`로 `/ieum` 별칭을 준비한다. [별칭 원본](references/claude-shortcut.md)은 플러그인 스킬로 요청을 전달하며 기존 명령·스킬이 있으면 덮어쓰지 않는다. 고객 프로젝트 폴더를 Claude Code 작업 폴더로 열고 새 세션의 명령 목록에서 확인한다. 아직 설정하지 않았다면 자연어로 “프로젝트이음으로 시작하고 짧은 명령도 준비해줘”라고 요청하게 한다. 다른 개인·관리자 스킬이 같은 이름을 사용하는지는 실제 호스트에서 확인한다.
- Claude Code 역할: 플러그인 루트 agents/의 `ieum-*` 정의를 사용한다. 예: `project-lifecycle-agent:ieum-backend`. 실제 목록에서 등록 여부를 확인하고 작업을 위임한다.
- Codex: Claude용 agents/를 자동 인식한다고 추측하지 않는다. 요청을 분석한 결과 전문 작업자 실행에 네이티브 역할 등록이 필요한 경우 역할 도구 `codex-preview <실제 프로젝트>` 결과를 확인하고 JSON 파일로 저장한 뒤 `codex-install <프로젝트> --file <미리보기 파일>`로 적용한다. 기존 엔진 프로젝트가 아니면 먼저 현재 폴더의 용도를 확인한다. 설치 캐시·전역 설정·config.toml은 변경하지 않는다.
- Codex 설치 결과는 설정 파일 추가이며 `host_loaded: false`다. 새 세션에서 역할 목록/호출 기능으로 실제 로딩을 확인한다. 현재 세션이 새 커스텀 역할을 인식하지 못해도 기본 작업자 도구가 있으면 `show`로 읽은 계약과 작업 묶음을 전달해 자동 위임을 계속한다. 하위 에이전트 도구 자체가 없을 때만 직접 역할 모드로 수행하고 그 제한을 명시한다.
- 설정 파일 충돌은 덮어쓰지 않는다. 사용자 변경·업데이트 차이를 확인하고 조율한다. 호스트 제한을 해결할 수 없을 때만 제한·대안을 보고한다. 도구 권한은 기존 세션 정책을 따른다.

마지막에 실제 산출물·검증 결과·남은 판단을 보고한다. 여러 역할이 실제로 실행됐는지, 역할 모드만 사용했는지 구분하고 사람 승인과 AI 검토를 혼동하지 않는다.
