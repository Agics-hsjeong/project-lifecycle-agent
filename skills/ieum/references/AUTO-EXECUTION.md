# 요청 기반 자동 역할 실행

## 선택 기준

이 규약은 실제 하위 에이전트 사용을 명시적으로 요청하는 스킬 지침이다. 사용자는 목표·자료·제약을 전달하며 역할 이름·팀·병렬이라는 말을 추가할 필요가 없다. 현재 주 에이전트가 조율자다. 설치된 호스트의 도구·상위 정책·사용자 단일 실행 지시는 그대로 따른다.

- 설명·도움말·현재 상태·한 문장 카피·사소한 단일 수정: 직접 처리. 역할을 나열하거나 작업자를 만들기 위한 작업을 추가하지 않는다.
- PRD·상세 정책·IA 등 여러 산출물: 요청에 필요한 po/spec/ia를 선택해 선행 산출물에 맞춰 순차 또는 독립 위임.
- 제안서·발표: proposal-strategist가 평가·주장·증거를 정리한 뒤 proposal-producer가 선택 템플릿으로 실제 파일 제작. 도구가 없으면 제한 기록.
- 비단순 구현: 기존 계약을 확인하고 backend/frontend/database/devops 중 해당 영역 작업자를 실행. 구현 후 QA 또는 reviewer 등 적절한 별도 작업자에게 검토를 자동 위임.
- UI 개선: ia/ui/ux-writer/design-system 중 문제 원인에 필요한 역할과 frontend·qa 연결. 실제 화면 없이 미적 품질을 검증했다고 하지 않는다.
- 보안·성능·검토: 해당 전문 검토자에 자동 위임. 보안 검토를 관련 없는 작업까지 의무화하지 않는다.
- 납품·배포·운영: devops/technical-writer 등 필요한 역할. 실제 외부 실행 권한은 기존 사용자 승인 범위를 따른다.

## 실행 순서

1. 기존 실행 스킬로 프로젝트·현재 단계·자료를 확인한다. 요청 범위에서 필요한 역할·실행 순서·담당 경로를 짧게 알리고 바로 진행한다. 역할 선택 계획만 내고 끝내지 않는다.
2. 각 작업자에게 실제 프로젝트 루트·REQ/TASK·목표·입력 파일·기준 버전·담당 경로·출력 파일·검증·반환 형식을 전달한다. 설치된 역할 정의 또는 role_agents.py show의 실제 계약을 사용한다.
3. Claude Code는 설치된 `project-lifecycle-agent:ieum-<role>`를 사용한다. Codex는 실제 로딩된 커스텀 역할을 사용하며, 현재 세션에서 인식되지 않으면 기본 작업자에 같은 계약을 명시 전달한다. 커스텀 역할 등록 때문에 사용자가 다시 요청해야 하는 절차로 중단하지 않는다.
4. 호스트의 실제 Agent/Task/spawn 도구를 호출하고 완료를 기다린다. 공유 계약은 먼저 정리하고 독립 경로만 병렬로 진행한다. 하위 에이전트는 추가 하위 에이전트를 만들지 않는다.
5. 근거가 되는 산출물·실행·검증 결과를 확인한다. 필요한 수정은 원 소유자에게 전달하고 검토를 다시 확인한다. 동일 원인의 실패가 두 번 반복되면 해당 작업을 차단 상태로 기록하고 독립 작업만 계속한다.
6. 공통 원장·실행 상태·HANDOFF는 주 에이전트가 기존 엔진의 revision·잠금·run 기록으로 직렬 갱신한다. 작업자에게 직접 state나 원장 수정을 맡기지 않는다.
7. 최종 보고에는 선택 역할·실제 실행 방식·완료 산출물·검증·잔여 판단을 간단히 포함한다. 실제 하위 작업자 식별자는 도구 결과에서 확인한 값만 적는다. 역할명이나 계획만으로 실행 증거를 만들지 않는다.

## 예외와 경계

권한·동시 실행 한도·도구 제한이 있으면 안전한 기본 작업자로 전환하거나 순차 진행한다. 실제 도구가 없을 때의 직접 수행은 별도 에이전트 실행으로 표현하지 않는다. 사용자에게 역할을 골라 달라고 되묻는 대신 역할 선택에 필요한 사업 범위가 실제로 불명확할 때만 질문한다. 요청 범위 밖 외부 발송·공개·운영 변경·구매까지 위임 권한으로 확대하지 않는다.

AI accept/revise/blocked는 검토 의견이다. 사람 승인·approved·수주·배포 권한을 대신하지 않는다. 단순 조회는 새 프로젝트·원장·실행 계획을 만들지 않는다. 기존 고객 프로젝트를 새 blueprint로 덮어쓰지 않는다.
