# 실행을 보여주는 관제 연결

사용자는 AI 코딩 호스트에서 목표·질문·수정 방향을 전달한다. 주 에이전트가 조율하고 관제는 관찰 화면으로 연결한다. 내부 구현과 검토를 위해 검토자 이름·승인 버튼·별도 프롬프트 작성을 요구하지 않는다. 화면 조작을 기다리지 말고 요청한 범위를 수행한다.

## 현재 호스트 실행

1. 연결된 실제 프로젝트·현재 원장·REQ/TASK를 확인한다. 관제를 요청한 이음 프로젝트에만 적용한다. 일반 코딩 요청에 관리 체계를 강제하지 않는다.
2. 역할별 작업 묶음과 담당 경로를 정리하고 실제 native 작업자를 실행한다. 호스트가 반환한 실제 ID만 사용한다.
3. 주 조율자가 `workspace-activity <project> --file <payload>`로 시작·행동·인계·결과를 보고한다. payload는 task_id, agent_id, role, provider, kind, summary와 고유 event_id를 사용한다. 지원 kind는 실제 도구의 계약을 확인한다. worker의 숨은 추론이나 원시 인자는 넣지 않는다.
4. 실제 도구를 호출하기 직전과 결과를 확인한 직후에 의미 있는 요약을 보고한다. 오래 걸리는 작업은 호스트가 확인한 활동과 상태를 전달한다. 완료·실패·대기 이유를 구분하고 마지막 확인 시각을 보존한다. 퍼센트를 시간에 따라 임의 증가시키지 않는다.
5. TASK/RUN 시작·완료는 기존 엔진으로 실제 근거와 검증을 기록한다. 활동 문장만으로 산출물 완료 상태를 만들지 않는다. 공통 기록은 주 에이전트가 직렬 갱신한다.
6. 구현 후 다른 역할의 독립 검토를 실행하고 결과·피드백을 원 소유자에게 전달해 수정·재검증한다. AI 검토는 workspace-review로 별도 기록하며 사람 승인으로 표현하지 않는다.
7. 질문·사업 판단·이미 주어진 범위를 넘는 외부 실행만 현재 대화에서 설명한다. 기존 권한은 반복 확인하지 않는다. 사람이 관제 버튼을 눌러야 다음 내부 역할이 시작되도록 임의 게이트를 만들지 않는다.

관제 서버는 `workspace-serve <project> --open`으로 연결한다. 별도 상주 실행 요청이 있을 때만 provider를 붙여 네이티브 CLI 실행기를 연결한다. 현재 앱 작업과 같은 TASK를 중복 실행하지 않는다. 기록하지 않은 다른 대화·도구 내역까지 자동으로 관찰한다고 주장하지 않는다.

## 기존 게이트와 이력

사용자가 내부 검토 자동화를 요청한 기존 관제 게이트는 required:false로 전환할 수 있다. 사람 결정·실패 이력은 보존하며 승인했다고 쓰지 않는다. 사업 단계 승인·수주·외부 발송·운영 배포 권한은 별개다.

호스트 기록에는 실제 시작/종료·담당 역할·파일 경로·테스트 결과·다음 담당자처럼 공개 가능한 사실만 넣는다. API키·토큰·원시 명령 인자·문서 전문·숨은 추론은 넣지 않는다. 연결 실패는 그대로 표시하고 가상 이벤트로 채우지 않는다.
