# 10분 발표 구성·대본 예시

텍스트 구성 예제이며 실제 PPTX·PDF 제출본이 아니다. 디자인 적용과 전체 슬라이드 렌더링은 실제 제작 단계에서 수행한다.

| 슬라이드 | 시간 | 핵심 메시지 | 평가 연결 |
| --- | --- | --- | --- |
| SLIDE-001 사업 이해 | 1분 | 접수부터 상태 확인까지 하나의 문의 기록 | EVAL-001 |
| SLIDE-002 수행 전략 | 2분 | 정책 확정 → 핵심 경로 → 운영 인수 | EVAL-001 |
| SLIDE-003 기능·권한 흐름 | 3분 | 고객과 담당자의 핵심 경로와 요청 단위 권한 검증 | EVAL-002 |
| SLIDE-004 일정·품질 | 2분 | 6주 가정, 범위 확정 후 기준선, 실제 증거 기반 검증 | EVAL-003 |
| SLIDE-005 운영·인수 | 2분 | 복구 절차·매뉴얼·릴리스 기록과 유지보수 연결 | EVAL-004 |

합계 10분.

## 발표 대본 요지

1. 고객이 문의를 접수한 뒤 다시 전화하지 않아도 상태를 확인할 수 있도록 하는 것이 목표입니다. 현재 처리 시간의 실측값은 착수 시 확인합니다.
2. 권한·보관 정책과 미확정 범위를 먼저 확정합니다. 이후 핵심 경로에 집중하고 운영 인수 준비를 병행합니다.
3. 고객은 자신의 문의를, 담당자는 부여된 범위를 처리합니다. 권한은 UI와 요청 모두에서 검증할 계획입니다. 검증 완료를 주장하는 단계는 아닙니다.
4. 제시한 6주와 40인일은 가상 사례의 가정입니다. 실제 인력·환경·추가 범위가 확정되면 산정을 조정합니다.
5. 납품 시 실제 테스트 결과와 배포·복구·운영 문서를 전달합니다. 운영의 장애·변경은 릴리스 이력에 이어갑니다.

## 예상 Q&A

- 알림 발송을 포함하나요? → 현재 미확정입니다. 대상·채널·실패 처리 조건을 확인한 뒤 영향과 범위를 정리합니다.
- 6주를 보장하나요? → 예제의 가정입니다. 실제 인력·인증·호스팅·변경 범위 확정 후 기준선을 협의합니다.
- 다른 고객의 문의를 볼 수 없다는 증거는요? → 요청 단위 권한 테스트를 계획하며, 실제 구현·검증 후 실행 증거로 제시합니다.
