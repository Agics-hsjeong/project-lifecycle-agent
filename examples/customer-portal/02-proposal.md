# 정성제안서 본문 예시 - 가상 사례

## 1. 사업 이해

이 사업의 핵심은 문의 접수 창구를 추가하는 것과 함께, 고객이 진행 상태를 확인하고 담당자가 답변 이력을 이어갈 수 있도록 하는 것이다. 분산된 접수·처리를 문의 단위의 기록으로 묶는다.

완료의 기준은 REQ-001~006의 수용 기준으로 구체화한다. 현재 처리 시간의 실측값은 없으므로 개선률이나 절감 효과를 실적처럼 제시하지 않는다. 착수 시 기준값과 운영 지표를 협의한다.

## 2. 수행 전략

첫째, 착수 시 인증·역할·보관 정책과 적용 범위를 확정한다. 둘째, 고객의 등록→상태 확인과 담당자의 분류→답변→상태 변경 경로를 우선 구현한다. 셋째, 운영 인수 문서를 구현과 병행해 검증·납품 단계에 연결한다.

## 3. 기능·기술 제안

고객 화면은 문의 등록·목록·상세, 운영 화면은 문의 분류·답변·상태 이력으로 나눈다. 공지는 비로그인 공개 읽기를 제공하되 편집 권한을 분리한다. 권한은 화면 표시뿐 아니라 서버 요청에서도 검증한다.

구체적인 기술 스택과 데이터 보관 정책은 고객 환경 확인 후 결정한다. 이 제안 단계에서 외부 연동·첨부파일·알림을 구현 완료 또는 계약 범위로 표현하지 않는다.

## 4. 수행 계획

6주 가정 일정은 1주 차 범위·설계, 2~4주 차 핵심 경로 구현, 5주 차 통합·권한·반응형 검증, 6주 차 고객 확인·배포 준비·인수로 구성한다. 실제 인력과 변경 범위를 확인한 뒤 기준선을 수립한다.

## 5. 운영·인수 계획

배포 전 실제 테스트 증거와 복구 절차를 확인한다. 납품 시 최종 파일 목록·버전·사용자 및 운영 매뉴얼을 함께 전달한다. 유지보수의 장애·변경은 요구사항과 릴리스 기록에 연결한다.
