# 요구사항 분석 결과 예시

가상 사례의 설명용 결과이며 실제 프로젝트 원장 ID는 생성 도구가 배정한다.

| 예시 ID | 근거 | 요구사항 | 수용 기준 예시 |
| --- | --- | --- | --- |
| REQ-001 | RFP 2.1 | 역할별 로그인과 조회 권한 | 고객 A가 고객 B의 문의를 UI·직접 요청 모두로 조회할 수 없음 |
| REQ-002 | RFP 2.2 | 문의 등록·조회 | 필수값 검증 후 등록되며 자신의 목록과 상세에서 상태 확인 가능 |
| REQ-003 | RFP 2.3 | 담당자 답변·상태 이력 | 답변자·변경 시각·이전/이후 상태가 기록되고 허용 역할만 변경 |
| REQ-004 | RFP 2.4 | 공개 FAQ·공지 | 비로그인 접근과 운영자 편집 권한이 분리됨 |
| REQ-005 | RFP 2.5 | 반응형·접근성 | 모바일·데스크톱 핵심 경로, 키보드 이동·레이블·오류 안내 확인 |
| REQ-006 | RFP 2.6 | 운영 인수 자료 | 배포·복구·사용자·운영 문서와 실제 테스트 결과가 제공됨 |

## 고객 질문

인증은 기존 SSO인가, 자체 계정인가? 개인정보 보관 기간과 문의 삭제 정책은 무엇인가? 첨부파일·이메일 알림은 이번 범위인가? 배포 환경과 운영 담당자는 누구인가? 실제 예산·인력·제출 기한은 무엇인가?

## 미확정 사항

알림·첨부·SSO 연동과 실제 운영 요건은 범위에 확정 반영하지 않는다. 답변 후 설계·공수·일정 영향을 분석한다.
