## 작업 폴더와 자료 준비

`내 프로젝트/`처럼 업무용 폴더를 열고 RFP를 첨부하거나 실제 경로를 알려주세요. 아래의 **A사·a-portal은 설명용 이름**입니다. 자신의 사업명과 식별자로 바꿉니다.

```text
Project Lifecycle Agent로 A사 고객 포털 사업을 시작해줘.
현재 작업 폴더를 업무 공간으로 쓰고 식별자는 a-portal로 해줘.
외주/SI 사업이고 제안요청서는 [실제 RFP 파일 경로]에 있어.

프로젝트와 참고 템플릿 폴더를 준비하고 RFP 원본을 등록해줘.
사업 검토 초안, 요구사항, 평가기준, 제출 조건과 고객 질문을 정리해줘.
미정인 예산·일정·실적은 가정 또는 확인 필요로 표시해줘.
환경 확인, 파일 생성과 기록 관리는 네가 처리해줘.
```

채팅 첨부라면 경로 부분을 “첨부한 RFP”로 바꿉니다. 에이전트가 실제로 접근할 수 있는 파일을 확보한 뒤 등록합니다.

## 에이전트가 준비할 것

1. `projects/a-portal/` 생성. 같은 이름의 기존 프로젝트를 덮어쓰지 않습니다.
2. RFP 원본·출처·버전 보존과 읽기 상태 확인.
3. 요구사항별 원문 페이지·절과 수용 기준, 고객 질문 정리.
4. 현재 단계·초안 문서·원장·HANDOFF.md와 다음 작업 기록.
5. 참고 템플릿 폴더와 실행 환경 준비.

사용자가 기능 테스트나 내부 원장을 작성할 필요는 없습니다. 실제 범위·예산·인력 등 사업 결정에 필요한 정보를 전달합니다.

## 자체 서비스도 시작할 수 있습니다

```text
Project Lifecycle Agent로 학원 상담·수강 신청 서비스를 시작해줘.
자체 서비스 프로젝트이고 식별자는 academy-service야.
대상은 소규모 학원이고 목표는 상담 누락과 신청 관리 시간 감소야.
사업 가설, 사용자 문제, MVP 범위, 성공 지표와 실행 계획을 작성해줘.
프로젝트 폴더와 관리 기록도 준비해줘.
```

기본 방법론은 하이브리드입니다. “2주 스프린트 중심으로 운영해줘”처럼 운영 방식을 전달할 수 있습니다. 자체 서비스의 제안 단계는 사업 실행안과 내부·투자 발표로 조정합니다.
