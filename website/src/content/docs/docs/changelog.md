## 2.0.0-beta.10 — 여러 실행의 흐름과 근거를 정확하게

2026-11-23. 여러 RUN에 걸친 QA 실패·개발 수정·재검증을 현재 TASK/STEP, 같은 근거 경로·SHA-256과 실제 순서로 연결합니다. 단계마다 RUN과 시도 차수를 표시하고 과거 범위·대체된·모호한 기록을 제외합니다.

실행 완료 기록과 현재 파일 검증을 분리합니다. 접근 불가와 실제 변경을 구분하며 접근 불가를 통과로 계산하지 않습니다. 선언된 생성 출력은 원 작성자가 바이트·해시를 보존해 발행하고 입력 원본·민감 경로·사용자 지정 권한은 유지합니다.

수집 중 정상 경합과 실제 연결·접근·형식 오류를 구분합니다. 마지막 정상 기록과 미처리 이벤트·커서를 보존하여 다음 수집을 이어가고, 지속적인 오류는 경고로 남깁니다. [관제 사용 가이드](../guides/workspace/)

## 2.0.0-beta.9 — 실패부터 재검증까지 한눈에

2026-11-23. 실행 현황 상단에 QA 실패 원인·개발 수정 요약·재검증 결과를 표시합니다. 최초 실패와 시도 차수·실제 시각은 최종 통과 뒤에도 보존하며, 같은 근거 경로·해시를 전달받은 개발 수정만 연결합니다. 누락·모호한 이력은 추정하지 않고 현재 실행과 과거 기록을 구분합니다.

작은 모바일 화면에서는 개요·알림·본문을 함께 스크롤해 각 카드를 읽습니다. 시도 기록은 읽기 전용으로 표시하며 완료 검증·진척도 계산·민감정보 보호를 유지합니다. [관제 사용 가이드](../guides/workspace/)

## 2.0.0-beta.8 — Windows 관측 파일 보안 저장과 검증 정리

2026-11-22. native 파일 교체 후 새 파일 소유자의 권한 때문에 관제 호스트 읽기가 지속 거부되는 원인을 추가 확인했습니다. 프로젝트의 기존 보안 기준으로 빈 임시 파일의 DACL을 준비·검증한 뒤 내용을 쓰고 교체합니다. 다른 허용·거부·보호 규칙은 보존하며 사용자 지정 소유권 충돌·미확인 권한은 중단합니다.

이미 영향받은 생성 native 파일만 정확한 경로·schema 1·상속 정책 일치·보호 해제·내용 바이트/해시 보존 조건을 모두 확인한 명시적 엔진 복구로 처리합니다. 소유권 강탈·광역 권한 부여·사용자 ACL 우회는 하지 않습니다. beta.8 신규 실제 검증과 최종 배포 결과는 별도 기록합니다.

명시적 복구에서 새 부모 항목은 기존 규칙이 유지되고 차집합 전체가 현재 유효 토큰의 Restricted SID와 정확히 같은 OS 상속 ALLOW capability일 때만 Modify 이하 최소 권한을 끝에 중복 없이 승계합니다. 일반 그룹·실계정·광역 권한·거부/명시/보호 정책·조회 실패는 거절하며, 일반 호스트의 Restricted SID가 없으면 추가 승계하지 않습니다.

업무 커밋·복원도 프로젝트 보안 기준으로 저장하고, 직접 만든 새 빈 폴더만 보안을 준비합니다. 기존 폴더 ACL은 유지합니다. 별도 `repair-project-access --path ...`는 정확한 엔진 메타데이터·events 등록 history만 전 대상 스키마·바이트/해시 검증 후 복구하며 입력·코드·일반 문서·pending 저널은 제외합니다.

표시용 과거 산출물 부모·TASK 입력의 접근 거부는 개별 접근 불가로 구분해 다른 작업·로그 조회를 유지합니다. 상대·비공개 경로 보호와 완료·게이트·영수증·해시 검증은 완화하지 않습니다.

실행기 검사는 승인 전제를 조회 부하·실행기 시작 전에 설정해 준비 단계의 잠금 경합을 분리하고, 두 작업의 자동 실행과 빈번한 관제 조회 검증은 유지합니다.

beta.7은 main CI 통과 후 태그했지만 릴리스 재검사의 Linux/Python 3.12 테스트 한 건이 실패해 플러그인 배포가 차단됐습니다. 기존 태그는 재작성하지 않으며 새 beta.8의 반복 검사·최종 CI·배포·설치 결과를 따로 확인합니다. 아래 beta.7의 첫 실패와 최종 실제 작업 근거는 당시 범위를 유지합니다.

[관제 사용 가이드](../guides/workspace/) · [검증 기록](https://github.com/Agics-hsjeong/project-lifecycle-agent/blob/main/docs/WORKSPACE-OBSERVATION-VALIDATION.md)

## 2.0.0-beta.7 — Windows 관측 파일 경합 처리

2026-11-22. 관리 native 읽기·쓰기를 같은 잠금으로 조율하고 관측 저장을 업무 변경 저널과 분리합니다. 짧은 Windows 공유 충돌은 유한 재시도하며 장기 오류는 보존·보고합니다. 실패 이벤트·로그 커서는 후속 수신에서 다시 처리합니다. 업무 커밋 마지막의 저널 삭제도 정확한 경로의 짧은 Windows 공유 충돌만 재시도하고 지속 오류에는 저널을 보존합니다. 실제 역할 실행·작업자 ID·원장 검증의 구분은 유지합니다.

beta.6 실제 할인 기능은 4/4 작업을 완료했지만 관제 갱신은 두 차례 끊겼습니다. 기능 성공과 관제 연속성을 구분하며 [원인 재현·후속 검증 기록](https://github.com/Agics-hsjeong/project-lifecycle-agent/blob/main/docs/WORKSPACE-OBSERVATION-VALIDATION.md)을 확인하세요.

첫 beta.7 실제 재검증에서는 저널 삭제 경합과 개별 산출물 읽기 거부로 HTTP 400이 총 78회 발생했습니다. 해당 실행은 관제 연속성 통과로 계산하지 않습니다. 저널 정리는 짧은 충돌만 재시도하고, 읽을 수 없는 산출물은 접근 불가·버전 미확인으로 표시해 다른 작업과 로그 조회를 유지합니다. 완료·승인 검증은 완화하지 않습니다.

[관제 사용 가이드](../guides/workspace/)

최종 실제 Codex 후속 작업은 세 역할 자동 실행과 3/3 검증 완료를 확인했습니다. 파일 읽기 부하 중 622회 조회에서 621회가 200이고, 업무 잠금 409 한 번은 1.329초 뒤 자동 회복했습니다. 400·5xx·전송 오류와 수동 복구는 없었습니다. Windows 전체 회귀 572개(플랫폼·권한 생략 7개)와 실제 관제 화면 대조 110개를 통과했습니다.

## 프로젝트이음 브랜드와 공개 사이트

2026-10-28 작성 기준입니다. 표시 브랜드를 프로젝트이음(Project Ieum)으로 정리하고 소개, 설치·업무 가이드, 고객 포털 공개 예제, 매뉴얼 다운로드와 피드백 경로를 구성했습니다.

설치 ID와 스킬 호출은 `project-lifecycle-agent` / `project-lifecycle`을 사용합니다. 당시 플러그인 엔진의 기준 버전은 **0.5.1**이었습니다. 사이트의 설명과 실제 설치 버전이 다르면 에이전트에게 로딩 버전을 확인하게 하세요.

## 0.5.1 - 첫 사용 준비

사용자 프로젝트의 참고 폴더·환경·자료 상태와 다음 작업을 준비합니다. 원본·분석 근거의 변경과 복구 필요를 확인합니다. 환경 점검과 문서·발표 비교 검수는 에이전트가 수행합니다.

## 0.5.0 - 과거 템플릿 활용

정성제안서·발표자료의 원본·버전·선택·스타일 분석·작업 사본과 생성본 비교 검수를 관리합니다.

## 0.4.0 - 제안 패키지

정성제안서, 평가 대응표, 발표자료, 대본·예상 Q&A와 제출 점검을 별도 산출물로 관리합니다.

## 0.3.0 - 실행 엔진

원본 입력, 원장·ID·관계, 검토·단계 이동, 변경 기록·복구와 인수인계 기능을 추가했습니다.
