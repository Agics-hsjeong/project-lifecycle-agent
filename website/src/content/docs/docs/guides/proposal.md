RFP의 지정 목차·평가기준·제출 형식을 우선하고 선택한 과거 자료의 디자인과 작성 패턴을 적용합니다.

## 제작 요청문

```text
a-portal의 RFP와 선택한 템플릿 분석 결과로 제안 패키지를 만들어줘.
RFP 지정 목차와 평가기준을 우선하고 대표 자료의 스타일을 적용해줘.

정성제안서, 공수·일정 산정서, 평가항목 대응표, 발표자료,
발표 대본·예상 Q&A, 제출 점검표를 작성해줘.
발표 시간은 RFP를 확인하고 규정이 없으면 15분 초안으로 표시해줘.
편집 가능한 DOCX·PPTX와 제출용 PDF를 가능한 도구로 제작해줘.

모든 페이지·슬라이드를 렌더링해 원본과 비교하고
잘림·겹침·글자 크기·이전 고객 정보·수치 불일치를 수정해줘.
평가항목별 제안서 절·슬라이드·증빙 연결도 검사해줘.
완료 파일 경로, 검수 결과와 아직 확인할 사업 결정을 알려줘.
```

## 함께 관리하는 결과물

| 결과물 | 내용 |
| --- | --- |
| 정성제안서 | 사업 이해, 수행·기술·관리·운영 전략 |
| 공수·일정 산정서 | 범위·인력·일정과 산정 근거 |
| 평가항목 대응표 | 평가기준 → 제안서 절 → 슬라이드 → 증빙 |
| 발표자료 | 발표 구성과 실제 슬라이드 |
| 대본·예상 Q&A | 발표 노트·시간 배분·질의응답 준비 |
| 제출 점검표 | 필수 파일·형식·버전·누락 점검 |

발표가 없는 사업은 실제 근거와 제외 사유를 남깁니다. 자체 서비스에는 사업 실행안과 내부·투자 피치로 조정합니다.

## 완료를 판단하는 기준

에이전트가 실제 제작 파일과 검수 근거의 경로를 안내합니다. **Markdown 구성안만 있는 상태는 최종 제출본 완료가 아닙니다.** 지정 형식 제작·렌더링 도구가 없다면 가능한 초안을 작성하고 실제 제한·미완료를 명시합니다. HWP가 필수면 RFP 조건을 먼저 확인하게 하세요.

에이전트는 평가 누락, 실제 PPTX 장수와 계획, 발표 시간·대본, 수치와 제출 파일을 점검합니다. 디자인은 전체 페이지·슬라이드를 렌더링해 비교합니다.

## 검수와 실제 사업 승인

- **에이전트:** 환경·기능 점검, 제작·렌더링·비교 검수와 기록 관리.
- **사용자:** 실제 예산·인력·실적·수행 범위와 사업 결정 제공.
- **승인:** 실제 사용자 결정 또는 승인 문서를 근거로 기록. 사람의 이름으로 임의 승인하지 않음.
- **외부 제출:** 사용자가 지정한 대상과 권한에 따라 별도로 수행.

승인 후 입력·범위·제출본·검수 근거가 바뀌면 재검토 대상입니다. 산정서·발표·대본의 관련 내용을 함께 맞추도록 요청하세요.
