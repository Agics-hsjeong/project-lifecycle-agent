**2.0.0-beta.7 기준 관제 안내입니다.** 공개 데모는 시뮬레이션이고 고객 프로젝트는 로컬 데이터로 연결됩니다.

Windows의 관측 읽기·쓰기는 같은 잠금으로 조율하고 관측 파일은 업무 변경 저널과 분리해 원자 교체합니다. 외부 프로그램이 파일을 오래 읽으면 새 관측이 지연될 수 있습니다. 마지막 정상 데이터와 별도 관측 지연 알림을 확인하세요. 미처리 이벤트·로그 커서는 충돌 해소 후 다시 처리하며, 관측 오류 때문에 업무 미완료 저널을 만들지 않습니다. 업무 커밋 뒤 저널 삭제의 짧은 Windows 공유 충돌도 유한 재시도하고, 지속 오류에는 저널과 기존 복구 검사를 유지합니다. 기존 업무 저널을 임의 삭제하거나 실행 종료만으로 검증 완료를 표시하지 않습니다.

## 이렇게 요청하세요

Codex·Claude Code에서 실제 프로젝트를 열고 말하세요.

```text
이음으로 이 기능을 구현해줘. 필요한 역할끼리 검토하고 고쳐서 테스트까지 끝내고,
역할별 현재 작업과 진행 상황을 관제에서 보여줘.
```

작업 요청·질문·방향 수정은 기존 AI 대화에서 이어갑니다. 에이전트가 역할을 선택하고 구현·검토·수정을 진행합니다. 내부 작업마다 관제에 이름을 입력하거나 승인 버튼을 누를 필요는 없습니다.

## 작업을 선택하고 로그를 확인하세요

밝은 작업 표와 짙은 사이드바를 사용하는 B안 화면입니다. PC에서 작업 행을 선택하면 오른쪽에 현재 담당 역할·호스트·파일·행동과 최근 로그가 표시됩니다. “작업 상세 보기”에서는 전체 활동과 파일 Diff를 확인합니다. 휴대폰에서는 작업 선택 시 전체 화면 상세로 전환합니다.

작업 상단의 상태 탭과 검색·필터로 범위를 좁힐 수 있습니다. 완료 비율은 선택한 실행 범위를 기준으로 하며 상태·검색 필터와 무관합니다. 최근 실행과 전체 기록의 수치는 별도로 확인하세요. “역할별 작업 흐름”에는 실제 실행 시도만 표시하고, 보고되지 않은 실행 시각은 미보고로 남깁니다. 모바일에서는 시간표 안쪽만 가로로 스크롤합니다. 왼쪽 타임라인 메뉴는 예정 일정과 실제 실행을 함께 보여주는 WBS입니다.

## 무엇을 볼 수 있나요?

| 화면 | 확인할 내용 |
| --- | --- |
| 실행 현황 | 진행 중·대기 중·완료된 작업과 실제 완료 비율 |
| 역할 활동 | 현재 담당자, 수행 중인 행동, 경과 시간과 마지막 활동 |
| 활동 로그 | 파일·도구 행동, 검증 시작·결과, 역할 간 전달과 수정 |
| 워크플로우 | 다섯 그룹과 작업 선후 관계, 현재 진행 위치 |
| 작업 지도 | 요구사항에서 작업·산출물·실제 작업자로 이어지는 근거 |
| WBS | 담당·예정 및 실제 일정과 일/주/월 타임라인 |

작업을 선택하면 활동·파일·Diff·의존성·일정과 리소스를 확인합니다. 실행기가 대기하는 것과 실제 작업자가 일하는 것을 구분합니다. 측정하지 않은 진행률을 임의로 올리거나 미집계 비용을 0으로 표시하지 않습니다.

## 최근 실행과 전체 기록을 구분하세요

기본은 가장 최근에 선언한 RUN의 진척입니다. 최신 실행이 실패했거나 완료 근거가 바뀌어도 과거 성공 실행으로 바꾸지 않습니다. 이전 실패·독립 실행과 대체된 STEP은 전체 이력에 남습니다. 예를 들어 **최근 실행 3/3 완료**여도 전체 기록은 **4/9 완료**일 수 있습니다. 전체 기록 수치도 함께 확인하세요.

작업 제목은 다음 행동과 따로 저장합니다. “없음”이나 완료 메모가 제목을 대체하지 않으며 구형 기록은 연결된 단계·최초 작업 기록으로 복원합니다. 화면을 열었다는 이유만으로 프로젝트 파일을 수정하지 않습니다.

## 실행 종료와 검증 완료는 다릅니다

역할 카드에는 실제 native 작업자 ID·호스트 세션과 마지막 관측을 연결합니다. **결과 확인 중**은 작업자가 끝났지만 완료 근거가 아직 기록되지 않은 상태입니다. 파일·입력·테스트 검증을 통과해야 완료로 집계하며, 기존 실패·변경됨 상태를 작업자 종료만으로 지우지 않습니다. 잠시 이벤트가 없으면 마지막 관측과 관측 지연을 표시하고 종료를 단정하지 않습니다.

업데이트 후 새 세션에서 로딩 버전과 연결을 확인하세요. 변경된 플러그인 훅의 신뢰 확인이 표시되면 해당 호스트 화면에서 변경 내용을 검토하고 허용해야 합니다. AI에게 “관제 연결과 실제 작업자 ID를 확인해줘”라고 요청하면 됩니다.

## AI 검토와 수정

필요한 역할이 결과를 검토하고 결함을 원 개발자에게 전달해 수정·재검증합니다. 실제 실패와 수정 이력을 남기고 같은 실패를 무한 반복하지 않습니다. 인증·권한·원본 충돌처럼 사람이 알아야 할 문제는 이유를 표시하고 현재 AI 대화에서 설명합니다.

사업 방향·계약·외부 발송·운영 배포 등 별도 권한이 필요한 판단은 기존 대화와 호스트 승인 흐름에서 처리합니다. AI의 내부 검토 통과를 사람의 사업 승인으로 기록하지 않습니다.

## 실제 연결인지 확인하세요

프로젝트 이름, 로컬 연결, 마지막 갱신 시각과 실제 역할 활동을 확인하세요. 현재 호스트에서 연결된 시작·종료 이벤트와 공개 활동만 표시합니다. 실제 작업자 ID는 세션·위임 연결로 TASK에 연결하며 역할명만으로 추정하지 않습니다. 연결하지 않은 다른 채팅의 도구 내역이나 숨은 추론을 자동 수집하지 않습니다.

별도 처리를 위해 로그인된 네이티브 CLI 실행기를 연결할 수도 있습니다. 컴퓨터와 실행기가 동작해야 하며 현재 앱 대화창에 메시지를 주입하는 방식은 아닙니다. [공개 데모](../../../workspace/)에는 로컬 실행기가 연결되지 않습니다.

연결이 끊기면 “이 프로젝트의 실제 관제 연결과 마지막 실행 상태를 확인해줘”라고 요청하세요. 연결 실패를 가상 데이터로 바꾸지 않습니다. 접속 링크의 비밀 토큰·고객 자료·원시 로그를 공개 공유하지 마세요.

[호스트 연결·운영 규약](https://github.com/Agics-hsjeong/project-lifecycle-agent/blob/main/docs/AUTOMATIC-EXECUTION.md)

## 자동 실행 연결과 갱신 대기

프로젝트 데이터 수신과 실제 실행기 연결은 따로 표시합니다. 실행기 시작이 지연되거나 실패하면 그 이유를 확인할 수 있습니다. 원장을 기록하는 동안 잠시 조회가 대기하면 마지막 정상 화면과 수신 시각을 유지하고 다음 조회에서 자동 복구합니다. 파일이 바뀌면 열린 Diff도 다시 불러옵니다.

별도 CLI 자동 실행기의 독립 검증은 로컬 Codex sandbox 도구를 사용하며 모델 API를 호출하지 않습니다. Claude 실행기에서도 같은 검증 도구가 필요하고 Windows는 MXC 지원이 필요합니다. 환경 준비는 에이전트가 확인합니다. 사용할 수 없는 격리를 비격리 검증으로 바꾸거나 검증 완료로 표시하지 않습니다.

Windows 독립 검증은 MXC의 Process Isolation API를 제공하는 Windows 11 환경이 필요합니다. 검증 기준인 Codex 0.170.0의 SDK는 24H2 빌드 26100.9278 이상 또는 25H2 빌드 26200.9278 이상을 명시합니다. Windows Server는 지원 환경으로 간주하지 않으며, 실제 API 사용 가능 여부를 실행 시 확인합니다. [MXC 지원 운영체제](https://github.com/microsoft/mxc/blob/b21120168d70befe12356411423266bfef168446/docs/backends/process-container/os-version-support.md)를 참고하세요.


## 검증 상태와 산출물 받기

감독자의 `등록 검증 통과`와 `호스트 검증 보고`를 구분합니다. 문서 전용 검수는 코드 실행 검사 성공이 아닙니다. 완료·실패·대기·적용 제외를 별도로 세며, 제외를 완료율의 분모에서 뺍니다. 완료 1·실패 1·제외 1이면 적용 대상 2개 중 완료 1개, 50%입니다.

산출물에서 미리보기·다운로드를 선택하세요. 등록된 파일의 현재 SHA와 인증을 확인하며 파일이 바뀌면 최신 목록에서 다시 선택합니다. PDF·PNG·JPEG만 제한된 미리보기를 제공하고 HTML·SVG는 다운로드로 받습니다. 32MiB를 넘는 파일은 현재 AI에게 원본 위치를 확인하게 하세요.

사용량이 일부만 보고되면 알려진 합계와 미보고 실행 수를 함께 봅니다. 예산은 보고된 값으로 다음 작업 시작을 제한하며 진행 중인 모델 호출의 청구 상한을 보장하지 않습니다. 별도 CLI 생성 작업자는 Claude Code 2.1.327 이상을 요구합니다.

Windows 격리에서 asyncio 내부 TCP가 필요한 ASGI TestClient 검증은 지원하지 않습니다. 에이전트가 환경 오류와 코드 오류를 구분하고 별도 신뢰 환경의 통합 검사 결과를 명시합니다. 제한을 숨기거나 검증 성공으로 바꾸지 않습니다.


### 파일 접근 지연 알림

다른 프로그램이 산출물을 배타적으로 열어 두면 `접근 불가 · 버전 미확인`으로 표시하고 해당 파일의 받기·미리보기를 잠시 중단합니다. 다른 역할의 작업과 로그는 계속 갱신합니다. 파일을 읽을 수 있게 되면 다음 조회에서 현재 해시와 받기 상태를 다시 확인합니다. 읽을 수 없는 완료 근거를 검증 통과로 취급하지 않습니다.
