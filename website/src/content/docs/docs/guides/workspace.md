**2.0.0-beta.4에 포함된 관제 기능입니다.** 공개 데모는 시뮬레이션이고 고객 프로젝트는 로컬 데이터로 연결됩니다.

## 이렇게 요청하세요

Codex·Claude Code에서 실제 프로젝트를 열고 말하세요.

```text
이음으로 이 기능을 구현해줘. 필요한 역할끼리 검토하고 고쳐서 테스트까지 끝내고,
역할별 현재 작업과 진행 상황을 관제에서 보여줘.
```

작업 요청·질문·방향 수정은 기존 AI 대화에서 이어갑니다. 에이전트가 역할을 선택하고 구현·검토·수정을 진행합니다. 내부 작업마다 관제에 이름을 입력하거나 승인 버튼을 누를 필요는 없습니다.

## 작업을 선택하고 로그를 확인하세요

밝은 작업 표와 짙은 사이드바를 사용하는 B안 화면입니다. PC에서 작업 행을 선택하면 오른쪽에 현재 담당 역할·호스트·파일·행동과 최근 로그가 표시됩니다. “작업 상세 보기”에서는 전체 활동과 파일 Diff를 확인합니다. 휴대폰에서는 작업 선택 시 전체 화면 상세로 전환합니다.

작업 상단의 상태 탭과 검색·필터로 범위를 좁힐 수 있습니다. 전체 완료 비율은 현재 필터와 무관합니다. “역할별 작업 흐름”에는 실제 실행 시도만 표시하고, 보고되지 않은 실행 시각은 미보고로 남깁니다. 모바일에서는 시간표 안쪽만 가로로 스크롤합니다. 왼쪽 타임라인 메뉴는 예정 일정과 실제 실행을 함께 보여주는 WBS입니다.

## 무엇을 볼 수 있나요?

| 화면 | 확인할 내용 |
| --- | --- |
| 실행 현황 | 진행 중·대기 중·완료된 작업과 실제 완료 비율 |
| 역할 활동 | 현재 담당자, 수행 중인 행동, 경과 시간과 마지막 활동 |
| 활동 로그 | 파일·도구 행동, 검증 시작·결과, 역할 간 전달과 수정 |
| 워크플로우 | 다섯 그룹과 작업 선후 관계, 현재 진행 위치 |
| 작업 지도 | 요구사항에서 작업·산출물·실제 작업자로 이어지는 근거 |
| WBS | 담당·예정 및 실제 일정과 일/주/월 타임라인 |

작업을 선택하면 활동·파일·Diff·의존성·일정과 리소스를 확인합니다. 실행기가 대기하는 것과 실제 작업자가 일하는 것을 구분합니다. 측정하지 않은 진행률을 임의로 올리거나 미집계 비용을 0으로 표시하지 않습니다.

## AI 검토와 수정

필요한 역할이 결과를 검토하고 결함을 원 개발자에게 전달해 수정·재검증합니다. 실제 실패와 수정 이력을 남기고 같은 실패를 무한 반복하지 않습니다. 인증·권한·원본 충돌처럼 사람이 알아야 할 문제는 이유를 표시하고 현재 AI 대화에서 설명합니다.

사업 방향·계약·외부 발송·운영 배포 등 별도 권한이 필요한 판단은 기존 대화와 호스트 승인 흐름에서 처리합니다. AI의 내부 검토 통과를 사람의 사업 승인으로 기록하지 않습니다.

## 실제 연결인지 확인하세요

프로젝트 이름, 로컬 연결, 마지막 갱신 시각과 실제 역할 활동을 확인하세요. 현재 호스트가 보고한 활동만 표시합니다. 연결하지 않은 다른 채팅의 도구 내역이나 숨은 추론을 자동 수집하지 않습니다.

별도 처리를 위해 로그인된 네이티브 CLI 실행기를 연결할 수도 있습니다. 컴퓨터와 실행기가 동작해야 하며 현재 앱 대화창에 메시지를 주입하는 방식은 아닙니다. [공개 데모](../../../workspace/)에는 로컬 실행기가 연결되지 않습니다.

연결이 끊기면 “이 프로젝트의 실제 관제 연결과 마지막 실행 상태를 확인해줘”라고 요청하세요. 연결 실패를 가상 데이터로 바꾸지 않습니다. 접속 링크의 비밀 토큰·고객 자료·원시 로그를 공개 공유하지 마세요.

[호스트 연결·운영 규약](https://github.com/Agics-hsjeong/project-lifecycle-agent/blob/main/docs/AUTOMATIC-EXECUTION.md)

## 자동 실행 연결과 갱신 대기

프로젝트 데이터 수신과 실제 실행기 연결은 따로 표시합니다. 실행기 시작이 지연되거나 실패하면 그 이유를 확인할 수 있습니다. 원장을 기록하는 동안 잠시 조회가 대기하면 마지막 정상 화면과 수신 시각을 유지하고 다음 조회에서 자동 복구합니다. 파일이 바뀌면 열린 Diff도 다시 불러옵니다.

별도 CLI 자동 실행기의 독립 검증은 로컬 Codex sandbox 도구를 사용하며 모델 API를 호출하지 않습니다. Claude 실행기에서도 같은 검증 도구가 필요하고 Windows는 MXC 지원이 필요합니다. 환경 준비는 에이전트가 확인합니다. 사용할 수 없는 격리를 비격리 검증으로 바꾸거나 검증 완료로 표시하지 않습니다.

Windows 독립 검증은 MXC의 Process Isolation API를 제공하는 Windows 11 환경이 필요합니다. 검증 기준인 Codex 0.170.0의 SDK는 24H2 빌드 26100.9278 이상 또는 25H2 빌드 26200.9278 이상을 명시합니다. Windows Server는 지원 환경으로 간주하지 않으며, 실제 API 사용 가능 여부를 실행 시 확인합니다. [MXC 지원 운영체제](https://github.com/microsoft/mxc/blob/b21120168d70befe12356411423266bfef168446/docs/backends/process-container/os-version-support.md)를 참고하세요.
