## 수주 후에도 같은 프로젝트를 사용하세요

```text
a-portal 사업을 수주했어. 첨부한 최종 계약서와 협상 결과를 등록해줘.
제안과 달라진 범위·일정·납품 조건을 비교해줘.
확정 근거를 반영하고 착수 계획, 역할, 마일스톤,
요구사항 기준선과 검수 기준을 준비해줘.
필요한 검토·미결정을 정리하고 현재 단계에서 가능한 작업을 진행해줘.
```

## 전체 단계

| 단계 | 주요 작업 |
| --- | --- |
| 사업 검토 | 목표·타당성·리스크와 제안 진행 검토 |
| 제안 | 정성제안서·산정·평가 대응·발표·제출 준비 |
| 착수 | 계약 범위·역할·일정·검수 기준 |
| 기획·설계 | 요구사항, 화면 흐름, 데이터·API·구조 |
| 디자인 | 디자인 기준·화면·컴포넌트 |
| 퍼블리싱 | 화면 구현, 반응형·접근성 |
| 구현 | 기능 개발과 요구사항·설계·코드 연결 |
| 검증 | 테스트·결함·회귀·수용 기준 |
| 배포 | 배포·복구 계획, 실행 증거와 릴리스 |
| 납품 | 검수·인수·매뉴얼·산출물 목록 |
| 유지보수 | 장애·변경·운영 점검과 릴리스 반복 |

단계는 실제 검토·완료 기준과 승인 근거에 따라 이동합니다. 문서나 범위가 바뀌면 영향을 검토합니다. 소규모 사업은 적용 제외 사유를 기록해 조정할 수 있습니다.

## 개발·검증 요청

```text
확정 요구사항으로 화면 흐름과 데이터·API 설계를 작성해줘.
승인된 우선순위 기능을 구현하고 관련 테스트를 실행해줘.
요구사항·설계·코드·테스트 연결과 작업 기록을 갱신해줘.
```

기술 스택, GitHub 저장소, 테스트 방법과 배포 대상을 알려주세요. 연결된 도구와 실제 권한 안에서 작업하고 브랜치·커밋·버전·검증 결과를 남깁니다.

## 고객 변경 요청

```text
고객 답변을 등록하고 추가 기능의 범위·공수·일정·설계 영향을 분석해줘.
변경 기록과 검토할 결정을 정리하고 승인된 범위의 작업을 진행해줘.
```

## 배포·납품 준비

```text
검증 결과로 배포 준비 상태를 점검해줘.
배포·복구 절차, 릴리스 기록, 납품 산출물 목록과 운영 매뉴얼을 정리해줘.
실제 실행 증거와 미완료 사항을 구분해 알려줘.
```

## 유지보수

```text
전달한 장애를 등록하고 원인을 분석해줘.
허용된 범위에서 수정과 회귀 테스트를 진행하고
요구사항·문서·릴리스·인수인계 기록을 갱신해줘.
```

AI가 배포 성공·검수 완료·사람의 승인을 임의로 만들어 기록하지 않습니다. 운영 변경은 부여된 대상과 권한을 따릅니다.
