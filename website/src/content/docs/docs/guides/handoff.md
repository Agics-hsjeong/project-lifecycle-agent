## 같은 고객 프로젝트 폴더를 여세요

새 채팅이나 다른 AI에서 `내 프로젝트/projects/a-portal/`을 엽니다. 두 제품에는 플러그인이 각각 설치되어 있어야 합니다.

```text
Project Lifecycle Agent로 이 프로젝트를 이어서 진행해줘.
project.json, 지침, HANDOFF.md, 원장과 실제 산출물을 확인해줘.
현재 단계, 최근 변경, 미완료 작업과 검토할 사항을 정리한 뒤
현재 승인된 범위에서 다음 작업을 진행해줘.
```

여러 프로젝트가 있는 상위 폴더라면 “a-portal을 이어서 진행해줘”처럼 대상을 지정합니다.

## 에이전트가 대조하는 내용

| 위치 | 확인할 내용 |
| --- | --- |
| project.json | 실제 현재 단계·사업 유형·기술 정보 |
| AGENTS.md · CLAUDE.md · process/ | 지침과 단계별 규칙 |
| HANDOFF.md | 최근 변경·검증·미결정·다음 작업 |
| registers/ | 요구사항·작업·산출물·리스크·검토 |
| 실제 문서·코드·테스트 | 이전 완료 주장과 실제 파일·증거 일치 |

사용자가 내부 관리 파일을 편집할 필요는 없습니다. 에이전트가 읽고 확인한 뒤 허용된 작업을 수행합니다.

## 다른 PC 또는 팀원과 공유한다면

필요한 원본·작업 파일·산출물·관리 기록을 안전하게 동기화합니다. 파일의 GitHub 저장 여부는 고객 데이터 공개 범위에 맞춰 결정합니다. 공개 플러그인에는 고객 자료가 들어 있지 않습니다.

공유되는 것은 **파일과 기록**입니다. Codex와 Claude Code의 대화 내용은 자동 동기화되지 않습니다. 같은 관리 파일을 동시에 수정하다 충돌이 생기면 에이전트가 최신 상태를 확인하고 사용자 변경을 보존하며 해결해야 합니다.
