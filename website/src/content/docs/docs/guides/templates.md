## 예전 자료의 사본을 넣으세요

```text
내 프로젝트/projects/a-portal/templates/
  qualitative/
    공공기관_정성제안서.docx
    플랫폼구축_정성제안서.pdf
  presentation/
    플랫폼구축_제안발표.pptx
    간결한스타일_발표.pdf
```

파일을 옮기지 않고 기존 자료 폴더의 실제 경로를 알려줘도 됩니다. 에이전트가 해당 프로젝트 안에 버전별 원본 사본을 보존합니다.

| 자료 | 권장 원본 | 그 밖의 참고 형식 |
| --- | --- | --- |
| 정성제안서 | DOCX | DOTX, PDF, HWP, HWPX, PNG/JPG/JPEG/WebP |
| 발표자료 | PPTX | POTX, PDF, PNG/JPG/JPEG/WebP |

DOCX/PPTX는 원본 구조를 활용한 작업 사본에 유리합니다. PDF·HWP·이미지는 호스트의 문서·OCR·시각 도구로 분석해 재구성합니다. 편집 가능한 원본과 같은 복원을 보장하지 않습니다. DOTX/POTX 변환도 호스트 도구에 따릅니다.

## 대표 스타일과 원하는 특징을 알려주세요

```text
a-portal의 templates 폴더를 등록하고 디자인과 작성 방식을 분석해줘.
정성제안서는 공공기관_정성제안서.docx,
발표자료는 플랫폼구축_제안발표.pptx를 대표 스타일로 사용해줘.
서체·색상·여백·표·도식, 목차 전개, 핵심 메시지,
근거 제시 방식과 페이지·슬라이드 구성 패턴을 정리해줘.
이전 고객명·가격·인력·실적은 새 사업의 사실로 사용하지 마.
```

여러 자료 중 대표가 불명확하면 에이전트가 후보 차이를 정리하고 선택을 요청합니다. 문서와 발표는 다른 자료를 선택할 수 있습니다. 새 파일이 추가되어도 기존 선택을 자동 변경하지 않습니다.

## 실제 처리 과정

1. **보존:** 원본·출처·해시·버전 등록과 중복 확인.
2. **관측:** DOCX/PPTX 편집 구조, 테마·마스터·레이아웃 등 추출.
3. **분석:** 렌더링된 실제 예시에서 스타일·문체·설득·증빙 패턴 확인.
4. **제작:** 선택한 원본의 구조를 활용해 이번 RFP의 새 내용 작성.
5. **검수:** 생성된 모든 페이지·슬라이드를 렌더링하고 원본 패턴과 비교.
6. **기록:** 선택·분석·교체 규칙·비교 근거를 프로젝트에 저장.

자동 구조 관측만으로 시각 검수를 완료하지 않습니다. 이전 고객 정보뿐 아니라 노트·주석·메타데이터의 잔존도 확인합니다. 검수 후 원본·분석·제출본이 바뀌면 다시 확인합니다.

## 회사 공통 폴더

작업 공간에 아래 폴더를 준비해 달라고 요청한 뒤 파일을 넣고 경로를 알려주세요.

```text
reference-templates/qualitative/
reference-templates/presentation/
```

필요한 원본만 해당 프로젝트에 등록합니다. 고객 자료를 플러그인 설치 캐시나 `blueprint/`에 넣지 마세요. 업무 저장소를 공개할 때도 고객 원본의 제외 설정을 요청합니다.

분석 규칙은 프로젝트 파일에 보존합니다. 모델 자체를 학습시키는 기능은 아닙니다. 자료가 호스트 모델에 전달되는 방식은 사용하는 제품의 데이터 정책과 설정을 따릅니다.
