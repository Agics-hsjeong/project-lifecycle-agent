이 문서는 **2.0.0-beta.9 기준**입니다. beta.9는 QA 실패 원인·개발 수정·재검증 차수를 실행 현황에 표시하고 모바일 읽기를 개선합니다. beta.8의 Windows 관측 경합 처리와 실제 실행 연결을 유지합니다. 기존 검증 무결성·민감정보 보호를 유지하며 실제 작업자 ID와 실행 상태 연결, 최근 실행·전체 기록 분리와 작업 제목 보존을 강화했습니다. [자동 역할 실행 가이드](../agents/)에서 사용법을 확인하세요. 기존 [v2.0.0-beta.1 릴리스](https://github.com/Agics-hsjeong/project-lifecycle-agent/releases/tag/v2.0.0-beta.1)에는 이 기능이 포함되지 않습니다. 안정판과 구분하고 재현 가능한 설치에는 공개된 릴리스 태그를 지정하세요. 기존 사용자는 실제 설치 소스·로딩 버전을 확인한 뒤 업데이트를 요청하세요.

## 새 프로젝트

“이 RFP로 SI 사업을 시작해줘”, “자체 제품의 첫 릴리스를 만들어줘”, “UI 없는 API 사업이야”, “기존 서비스 유지보수야”라고 요청합니다. 에이전트가 각각 SI 11단계·제품 6단계·API 9단계·유지보수 6단계를 적용합니다. 제품은 외부 입찰 제안·디자인 단계를 강제하지 않습니다.

## 기존 프로젝트와 폴더 이동

```text
이 프로젝트의 현재 경로와 설치 버전을 확인해줘.
v2 이행 미리보기의 변경 범위와 관리정보 백업을 확인한 뒤 적용해줘.
기존 문서·원본·ID·단계는 유지하고 실제 검토가 필요한 항목을 알려줘.
```

에이전트가 upgrade-preview → upgrade를 수행합니다. 변경하는 project.json만 백업하며 고객 자료 전체의 백업을 뜻하지 않습니다. 새 양식으로 덮어쓰지 않습니다. 프로필도 자동 변경하지 않습니다.

폴더 이동 후에는 새 실제 경로에서 이어갑니다. 내부 근거는 상대 경로를 사용하고 외부 템플릿 폴더는 접근 상태를 다시 확인합니다.

## 작은 릴리스와 작업 재개

“이번 릴리스에는 REQ-001·002만 넣고 나머지는 백로그로 남겨줘”라고 요청하세요. 작업은 입력·의존성·예상 출력·실제 결과와 함께 기록합니다. 중단 후 “실제 결과 파일을 대조하고 유효한 단계부터 이어가줘”라고 요청하면 입력이나 증거가 바뀐 결과를 재검토합니다.

## 검수·현황·되돌리기

- “제안서와 발표자료의 실제 출력과 전체 페이지를 검수해줘.” 제출본·PDF·전체 페이지 이미지·검수 기록을 연결합니다.
- “현재 프로젝트 현황 화면을 만들어줘.” 프로젝트의 reports/overview.html에 로컬 현황을 생성합니다. 외부 서버로 올리지 않습니다.
- “방금 관리정보 수정을 되돌려줘.” undo 미리보기와 충돌 검사를 적용합니다. 코드·문서의 일반 편집은 Git/별도 백업으로 복원합니다.
- “방금 v2 이행을 되돌려줘.” 이후 수정이 없을 때만 전용 이행 복원 절차를 사용하고 이력은 보존합니다.

## 확인된 한계

베타는 자동 결재·무인 배포·중앙 협업 서버가 아닙니다. 실제 승인과 업무 결정은 근거가 필요하며, Word/PowerPoint의 내용·스타일과 실제 배포 성공은 해당 호스트의 제작·검수·실행 결과로 확인합니다. 고객 자료로 제품 개발 테스트를 할 필요는 없습니다.


## beta.8에서 달라진 점

Windows native 파일 교체 후 관제 호스트의 읽기가 계속 거부되는 권한 문제를 추가로 처리합니다. 프로젝트의 기존 보안 기준으로 빈 임시 파일의 DACL을 준비·검증한 뒤 관측 내용을 쓰고 교체합니다. 다른 허용·거부·보호 규칙은 보존하며, 미확인 권한이나 사용자 지정 소유권 충돌은 중단합니다.

이미 영향받은 생성 관측 파일은 경로·스키마·상속 정책·내용 해시 등 안전 조건을 모두 만족할 때만 명시적 엔진 복구를 사용합니다. 부모 정책의 새 항목은 기존 규칙을 모두 유지하고 현재 유효 토큰의 Restricted SID와 정확히 같은 OS 상속 ALLOW capability만 존재할 때, Modify 이하 최소 권한을 중복 없이 끝에 승계하는 경우로 제한합니다. 일반 그룹·실계정·광역 권한·거부/명시/보호 정책·조회 실패는 허용하지 않습니다. 일반 호스트에 Restricted SID가 없으면 새 항목을 승계하지 않습니다. “이음, 공유 충돌과 권한 문제를 진단하고 안전 조건을 만족하는 관측 파일만 엔진으로 복구한 뒤 실제 갱신을 확인해줘”라고 요청하세요. 엔진 메타데이터는 별도 `repair-project-access`에서 정확한 경로 허용목록과 전 대상 스키마·바이트/해시 보존 검사를 따릅니다. 입력·코드·일반 문서·pending 저널은 제외하며 기존 폴더 ACL은 바꾸지 않습니다. 업무 커밋·복원도 보안 기준을 전달하고 새 빈 폴더만 준비합니다. 모든 사용자에게 접근을 허용하지 않습니다. [상세 복구 범위](https://github.com/Agics-hsjeong/project-lifecycle-agent/blob/main/docs/ENGINE.md)를 따릅니다.

실행기 부하 검사의 승인 전제는 부하·실행기 시작 전에 설정하고 두 작업의 자동 실행·빈번한 조회 검증은 유지합니다. beta.7은 태그 이후 릴리스 재검사에서 Linux 테스트 한 건이 실패해 플러그인 배포가 차단됐습니다. 기존 태그를 다시 쓰지 않고 새 버전으로 검증하며, 최종 CI·설치 결과는 별도로 기록합니다.

## beta.7에서 달라진 점

Windows의 관측 파일 읽기·쓰기를 같은 잠금으로 조율하고 native 저장을 업무 변경 저널과 분리합니다. 짧은 공유 충돌은 유한 재시도하고 장기 오류는 실제 원인으로 보고합니다. 외부 읽기가 유지되면 새 관측 반영은 늦어질 수 있으며, 직전 정상 데이터와 미처리 이벤트·로그 커서를 보존해 후속 수신에서 다시 처리합니다. 업무 커밋 마지막의 저널 삭제도 정확한 경로의 짧은 Windows 공유 충돌만 재시도하며 지속 오류에는 저널을 남깁니다. 기존 업무 미완료 저널의 복구 검사는 유지합니다.

[경합 재현·실제 작업 검증 기록](https://github.com/Agics-hsjeong/project-lifecycle-agent/blob/main/docs/WORKSPACE-OBSERVATION-VALIDATION.md)

## beta.6에서 달라진 점

호스트의 시작·종료 이벤트와 실제 native 작업자 ID를 명시 TASK 위임에 연결합니다. 실행 종료는 검증 완료가 아니며 결과 확인 중·원장 실패·변경된 근거를 구분합니다. 진척도는 최근 선언 RUN 또는 명시 범위 기준이고 전체 기록은 별도 보존합니다. 최신 실패를 과거 성공으로 숨기지 않습니다. 다음 행동이 완료 메모로 바뀌어도 작업 제목을 유지합니다.

업데이트 후 새 세션에서 실제 로딩 버전·훅 연결을 확인합니다. 호스트가 변경된 훅 신뢰 검토를 요구하면 제품 UI에서 확인해야 합니다. [관제 사용법](../workspace/)에서 범위와 실제 실행을 읽는 방법을 확인하세요.

## beta.5에서 달라진 점

검증한 파일만 반영하며 코드 작업의 빈 검사 계획을 거부합니다. 필요한 입력만 전달하고 자격 증명을 차단·마스킹합니다. 관제는 완료·실패·대기·제외, 감독자 검증과 호스트 보고, 알려진 사용량과 미보고 실행을 구분합니다. 파일 미리보기와 다운로드는 인증·현재 SHA를 확인합니다.

외부 의존성이 필요하면 에이전트가 lockfile에 결속한 검증 환경을 준비합니다. 별도 Claude 생성 실행기는 Claude Code 2.1.327 이상을 확인합니다. Windows의 네트워크 차단 격리는 asyncio 내부 TCP가 필요한 ASGI TestClient를 지원하지 않아 환경 오류로 빠르게 끝냅니다. 스키마·순수 로직의 격리 검사와 별도 신뢰 환경의 ASGI 통합 검증을 구분합니다.
