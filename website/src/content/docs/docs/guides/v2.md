현재 베타 기준은 **2.0.0-beta.1**입니다. [베타 릴리스](https://github.com/Agics-hsjeong/project-lifecycle-agent/releases/tag/v2.0.0-beta.1)에서 ZIP과 매뉴얼을 받을 수 있습니다. 안정판과 구분하고, 재현 가능한 설치에는 이 태그를 지정하세요. 기존 사용자는 에이전트에게 실제 설치 소스·로딩 버전을 확인한 뒤 업데이트를 요청하세요.

## 새 프로젝트

“이 RFP로 SI 사업을 시작해줘”, “자체 제품의 첫 릴리스를 만들어줘”, “UI 없는 API 사업이야”, “기존 서비스 유지보수야”라고 요청합니다. 에이전트가 각각 SI 11단계·제품 6단계·API 9단계·유지보수 6단계를 적용합니다. 제품은 외부 입찰 제안·디자인 단계를 강제하지 않습니다.

## 기존 프로젝트와 폴더 이동

```text
이 프로젝트의 현재 경로와 설치 버전을 확인해줘.
v2 이행 미리보기의 변경 범위와 관리정보 백업을 확인한 뒤 적용해줘.
기존 문서·원본·ID·단계는 유지하고 실제 검토가 필요한 항목을 알려줘.
```

에이전트가 upgrade-preview → upgrade를 수행합니다. 변경하는 project.json만 백업하며 고객 자료 전체의 백업을 뜻하지 않습니다. 새 양식으로 덮어쓰지 않습니다. 프로필도 자동 변경하지 않습니다.

폴더 이동 후에는 새 실제 경로에서 이어갑니다. 내부 근거는 상대 경로를 사용하고 외부 템플릿 폴더는 접근 상태를 다시 확인합니다.

## 작은 릴리스와 작업 재개

“이번 릴리스에는 REQ-001·002만 넣고 나머지는 백로그로 남겨줘”라고 요청하세요. 작업은 입력·의존성·예상 출력·실제 결과와 함께 기록합니다. 중단 후 “실제 결과 파일을 대조하고 유효한 단계부터 이어가줘”라고 요청하면 입력이나 증거가 바뀐 결과를 재검토합니다.

## 검수·현황·되돌리기

- “제안서와 발표자료의 실제 출력과 전체 페이지를 검수해줘.” 제출본·PDF·전체 페이지 이미지·검수 기록을 연결합니다.
- “현재 프로젝트 현황 화면을 만들어줘.” 프로젝트의 reports/overview.html에 로컬 현황을 생성합니다. 외부 서버로 올리지 않습니다.
- “방금 관리정보 수정을 되돌려줘.” undo 미리보기와 충돌 검사를 적용합니다. 코드·문서의 일반 편집은 Git/별도 백업으로 복원합니다.
- “방금 v2 이행을 되돌려줘.” 이후 수정이 없을 때만 전용 이행 복원 절차를 사용하고 이력은 보존합니다.

## 확인된 한계

베타는 자동 결재·무인 배포·중앙 협업 서버가 아닙니다. 실제 승인과 업무 결정은 근거가 필요하며, Word/PowerPoint의 내용·스타일과 실제 배포 성공은 해당 호스트의 제작·검수·실행 결과로 확인합니다. 고객 자료로 제품 개발 테스트를 할 필요는 없습니다.
