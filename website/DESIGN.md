# 프로젝트이음 웹 디자인 기준

갱신: 2026-11-03. GitHub Pages의 기존 주소·브랜드·공개 범위를 유지한다.

## 방향과 정보 구조

설치 안내에 더해 동작 구조와 목표 시스템을 시각적으로 설명한다. 입체 단계 탐색 → 실행 아키텍처 → 프로젝트 유형별 흐름 → 목표 시스템 → 팀 템플릿 → 맞춤 첫 요청문 → 제품별 설치 → 문서·예제·FAQ 순서다.

- 따뜻한 흰 바탕·차콜 본문·청록 브랜드를 기본으로, 깊은 녹색의 기술 도면과 옅은 세이지의 목표 시스템 도면을 대비시킨다. 격자와 선은 정보의 연결과 계층을 표현한다.
- 큰 한글 제목·정렬·여백·얇은 구분선을 사용한다. 입체 이미지는 입력·관리·산출물의 관계를 표현한다. 가상 진행률·고객 후기·이용 수치는 넣지 않는다.
- 첫 화면의 연결 그림은 개념 시각화다. 아키텍처는 실제 스킬·Python 엔진·프로젝트 파일의 관계를 표현한다. 작업 수행 주체는 활성 호스트이며 별도 상시 서버나 두 제품 간 자동 대화 동기화로 설명하지 않는다.
- 목표 시스템은 공개 가상 RFP의 2.1–2.6을 해석한 기술 제품 중립 개념 설계다. 실제 구축 화면으로 제시하지 않는다. 인증 방식·기술 제품·호스팅은 미확정이다. 비로그인 FAQ·공지와 개인 문의의 권한 경계를 구분한다.
- 접근 제어·데이터 흐름 버튼은 해당 구성요소를 강조하고 설명을 갱신한다. aria-pressed와 라이브 설명을 사용하며 키보드로 조작할 수 있다.
- SI 11·제품 6·API 9·유지보수 6단계 선택은 실제 엔진 프로필과 맞춘다.
- Codex의 설치 요청문과 Claude Code의 설치 명령을 구분한다. 복사 실패 시 내용을 선택해 직접 복사할 수 있게 한다.
- 모바일·태블릿에서는 글자를 작게 축소하는 대신 별도 세로형 도식을 사용한다. 구조도 원본 SVG도 새 탭으로 제공한다.

## 서체와 시각 자산

Pretendard 가변 서체를 자체 호스팅한다. 원본: https://github.com/orioncactus/pretendard. SIL Open Font License 1.1 전문과 저작권 고지는 public/fonts/OFL.txt에 함께 배포한다. 기존 프로젝트이음 로고를 유지한다.

세 종류·두 화면 구성의 SVG 6개는 이 저장소에서 직접 작성한 원본이다. 확대해도 선명하고 각각 7 KB 미만이다. 외부 이미지·모델 생성 비트맵·새 런타임 의존성을 추가하지 않는다. 생성 소스와 수정 방법은 [도식 안내](public/diagrams/README.md)를 참고한다. 목표 시스템은 HTML에 SVG를 포함해 강조 상태를 연결한다. 정적 개념 이미지의 가로형·세로형 원본도 함께 보관한다.

## 검증 범위

- Astro 프로덕션 빌드·사이트 버전 검사·HTML 16페이지의 로컬 링크와 자산 검사.
- 격리된 Windows Edge/Playwright에서 1440·1024·768·640·390·320px 화면과 SVG 텍스트 영역 검사. 데스크톱·모바일 도식을 캡처해 시각 검수.
- 전체·접근 제어·데이터 흐름 전환, Enter 조작, 선택 상태·강조 테두리·설명 갱신, 화면별 도식 선택, 중복 ID 없음, reduced-motion 설정 확인.
- 네 프로젝트 유형·키보드 방향키·두 제품의 클립보드 복사·복사 실패 대안·FAQ·모바일 메뉴·문서 탐색·Ctrl+K 한국어 검색 확인.
- 홈 데스크톱/모바일·문서 밝은 데스크톱/어두운 모바일에서 axe-core WCAG 2 A/AA·2.1 A/AA 자동 검사. SVG 겹침 때문에 자동 판단을 보류한 색 대비는 명시한 전경·배경 조합으로 계산하고 시각 검수한다. 모든 장애 환경에 대한 인증이나 전수 적합성 보증을 뜻하지 않는다.
- 브라우저 오류·실패한 HTTP 리소스 확인.

웹 UI·시각 자료만 변경하며 플러그인 실행 코드·고객 프로젝트·기존 릴리스 태그는 변경하지 않는다. 실행 기록과 캡처는 로컬 .test-output/site-design에 보관한다.

## 랜딩과 문서의 통합 경험

- tokens.css의 공통 색상·서체·재질과 Brand.astro의 로고 잠금을 랜딩과 문서 전체에 사용한다. 깊은 청록·남색, 민트와 라벤더 빛, 얇은 유리 경계를 조합한다. 밝은/어두운 문서 테마도 같은 계열을 따른다.
- 첫 화면은 ProjectExplorer의 입체 코어·연결 궤도와 5개 단계 버튼이다. 선택에 따라 실제 업무 설명·산출물·기록 경로를 갱신하며 흐름 미리보기임을 표시한다. 원본 정적 SVG도 재사용용으로 남긴다.
- StartBuilder는 AI 2종·프로필 4종·템플릿 활용 조건으로 실제 대화에 붙여넣을 요청문과 설치 링크를 만든다. 랜딩·시작 가이드·첫 프로젝트 문서에서 같은 컴포넌트를 사용한다. 고객 자료를 받거나 업무를 실행하는 웹 서비스는 아니다.
- 문서는 Starlight의 공식 컴포넌트 확장으로 헤더·사이드바·제목·하단을 통일한다. 기존 검색·목차·페이지 이동·테마·모바일 메뉴를 유지한다. 읽기 시간은 본문 분량에 따른 대략적인 값이며, 진행 막대는 스크롤 위치를 표시한다.
- 문서 링크 복사·맨 위로 이동·문서별 피드백 작성 링크를 제공한다. 피드백 링크는 GitHub 작성 화면으로 이동하며 자동으로 게시하지 않는다.
- 스크롤 등장 효과·포인터 조명·입체 코어의 완만한 움직임은 reduced-motion 설정을 존중한다. 탭이 숨겨지면 장면 움직임을 멈춘다. JavaScript가 없으면 문서 본문과 기본 요청문은 읽을 수 있고 요청문을 직접 선택해 복사할 수 있다.
- 문서 본문에서 사용해도 컨트롤의 간격이 흐트러지지 않도록 Markdown 간격을 분리하고, 컨테이너 너비에 맞춰 요청문 도구를 재배치한다. 좁은 화면에서 전체 도식·읽기·탐색을 유지한다.

### 이번 통합 변경의 검증

로컬 Windows Edge에서 랜딩 10개 너비, 문서 14개 경로의 1440·390·320px 가로 넘침, 단계 선택·방향키, AI/프로필별 요청문, 복사·권한 실패 대안, 테마·Ctrl+K 한국어 검색·읽기 진행·맨 위로·모바일 메뉴를 확인했다. 스크립트 비활성 상태에서도 기본 요청문과 문서를 확인했다. 지정한 8개 화면·테마의 axe-core 자동 검출 위반은 0건이다. SVG·그라디언트의 자동 판단 보류는 화면과 명시 색 조합으로 검수하며, 전수 접근성 인증으로 설명하지 않는다. 실행 기록은 로컬 .test-output/unified-experience에 보관한다.

## 모바일·초심자 동선

설치 단계의 모바일 순서는 제목·입력 위치 → AI 선택/개별 복사 → 다음 단계 → 추가 설명이다. 설치·단계·복사 UI는 공통 컴포넌트로 재사용한다. 초심자 진입점은 docs/quickstart이며, 설치/프로젝트/템플릿/제작/결과를 URL 상태로 탐색한다. 안내 단계는 실제 업무 완료 판정과 분리한다. 주요 조작 44px·모바일 입력 16px을 실제 계산 스타일로 검사한다. 세부 결과와 검증 범위는 [MOBILE-UX-AUDIT.md](MOBILE-UX-AUDIT.md)를 따른다.
