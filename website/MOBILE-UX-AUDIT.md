# 모바일·초심자 사용성 점검

점검일: 2026-11-03. 공개 사이트의 수정 전 화면을 기준으로 진단하고 로컬 변경을 검증했다. 공개 후 같은 터치 경로를 다시 확인한다.

## 확인한 문제와 반영

| 문제 | 사용자에게 생기는 혼동 | 반영 |
| --- | --- | --- |
| 설치 선택보다 세부 설명이 먼저 나옴 | 어느 AI에서 무엇을 실행할지 늦게 보임 | 모바일에서 AI 선택·복사 패널을 설명보다 먼저 배치 |
| 최초 #install 진입 위치가 폰트 로딩 뒤 어긋남 | 작은 화면에서 제목·선택 탭이 헤더 밖으로 밀림 | 사용자가 스크롤하지 않은 첫 진입만 폰트 로딩 후 위치 보정 |
| Claude Code의 두 명령을 통째로 복사 | 한 줄씩 실행해야 하는 순서를 놓침 | 번호가 붙은 개별 복사 블록을 랜딩·설치 문서·가이드에서 공유 |
| 설치 이후의 다음 행동이 약함 | 설치 페이지에서 멈추거나 문서를 다시 찾음 | 선택한 AI를 유지해 프로젝트 단계로 이어지는 버튼 추가 |
| 원본 전달·템플릿 선택·제작 요청이 여러 문서에 분산 | 어디에 파일을 넣고 언제 제작을 요청하는지 파악하기 어려움 | 설치 → 프로젝트 → 템플릿 → 제작 → 결과 받기의 5단계 가이드 |
| 일부 주요 버튼은 37~42px, 입력은 12px | 작은 터치 영역, 모바일 입력 포커스 확대 가능성 | 주요 조작 영역 44px 이상, 요청문·프로필 입력 16px. 기존 위젯의 우선순위 덮어쓰기도 수정 |
| 웹페이지와 실제 작업 공간의 경계가 약함 | 웹페이지에 자료를 넣으면 생성되는 것으로 오해 | 업무 폴더를 연 AI에 원본·요청을 전달하는 위치와 실제 파일을 받는 기준 명시 |

## 따라하기 기준

1. 사용하는 AI의 설치 요청 또는 개별 명령을 복사한다.
2. 새 세션과 업무 폴더에서 RFP를 전달하고 실제 생성 경로를 에이전트에게 받는다.
3. 예전 제안서·발표자료를 해당 프로젝트의 templates 하위 폴더에 넣거나 AI에 접근 가능한 원본을 전달한다.
4. 정성제안서·발표자료의 대표 스타일을 각각 선택하고 RFP·선택 원본으로 제작을 요청한다.
5. 실제 완성 파일 경로·형식·버전과 전 페이지 출력 검수 근거, 미완료·사업 결정을 에이전트에게 받는다.

안내 단계 이동은 업무 완료·승인을 기록하지 않는다. 복사한 명령이나 요청문을 웹페이지가 실행하지 않는다. 단계 요청에는 선택한 호스트의 실제 스킬 호출 이름을 사용하며 선택은 URL의 host·step으로 새로고침·상세 문서에서 돌아오기 시 복원한다. 개인 프로젝트명·고객 원본을 저장하는 기능은 추가하지 않았다.

## 검증

- Windows Edge의 Chromium 기반 터치 에뮬레이션. iPhone 13 크기(390×664), Pixel 7 크기(412×839), 작은 화면(320×568), 가로 화면(844×390)과 태블릿(768×1024).
- 실제 tap으로 메뉴·설치 선택·복사·다음 안내·AI 변경·단계 전환·이전/다음·모바일 검색·문서 사이드바를 확인했다. 두 AI의 프로젝트·템플릿·제작·결과 요청문과 클립보드 원문을 비교했다.
- 설치 다음 버튼의 AI 보존, 새로고침/브라우저 뒤로 후 단계 복원, 제목 포커스·헤더 가림, 복사 거부 시 전체 텍스트 선택을 확인했다.
- 주요 안내·복사·검색·메뉴의 44px 영역, 기존 요청문 생성기의 실제 16px 입력, 가로 넘침을 측정했다. 키보드 Enter/Space와 스크립트 비활성 시 전체 5단계·기본 요청문도 확인했다.
- 7개 화면·테마 상태의 axe-core WCAG 2 A/AA·2.1 A/AA 자동 검출 위반 0건. SVG·그라디언트 등의 자동 판단 보류는 시각 검수 대상으로 남기며 전수 적합성 인증으로 설명하지 않는다.
- 기존 문서 14개 경로와 랜딩 10개 너비, 요청문 생성·복사·검색·테마·진행 표시·모바일 메뉴의 회귀 검사도 통과했다.
- 증거: 로컬 .test-output/mobile-onboarding의 baseline.json, results.json, extra-results.json, accessibility.json과 전후 화면.

## 범위의 한계

기기 이름은 화면·터치 환경 설정이다. 실제 iPhone/Pixel 하드웨어, iOS Safari 엔진·가상 키보드에서 수행한 실기기 시험은 아니다. 16px 입력은 포커스 확대를 줄이기 위한 구현 보완이며 실제 Safari 동작의 인증이 아니다.

이번 점검은 웹 안내·탐색·복사 및 요청문 내용의 연결을 검증했다. 두 제품에 플러그인을 새로 설치하거나 고객 원본으로 DOCX/PPTX를 실제 제작하는 호스트 행동 검증은 수행하지 않았다. 실제 실행·문서 제작은 호스트의 환경·도구와 고객 결정에 따른다. 개발 검증 조건으로 고객 템플릿 제출을 요청하지 않았다.
