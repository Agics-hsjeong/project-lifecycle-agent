# 검증·보호·관제 품질 개선 기록

2026-11-22 · 2.0.0-beta.5 출시 전 검증 · 이전 공개 기준 2.0.0-beta.4

검증 무결성과 민감정보 경계를 우선 수정하고, 실제 Codex·Claude Code 및 실제 라이브러리를 사용하는 별도 참조 프로젝트로 검증했다. 고객 운영 프로젝트를 검사했다는 의미는 아니다. 기존 고객 자료를 복사하거나 외부로 제출하지 않았다. 연구·특허·사업 초안은 공개 패키지에 포함하지 않는다.

## 실제 실행 결과

- **Codex 0.170.0**: 기본 Windows PowerShell이 정상 실행되는 상태에서 외부 파일 읽기·쓰기의 실제 권한 거부를 확인했다. 허용된 산출물 작성과 반영은 성공했다.
- **Claude Code 2.1.327**: 외부 Read/Write/Glob 도구 거부, 담당 파일 Write와 구조화 결과 전달·반영을 확인했다. 이 버전 이상만 생성 작업자를 시작한다.
- 위 경계 시험의 문서는 `artifact_only`다. 코드 검사 통과로 표시하지 않는다.
- **FastAPI 0.165.0 / pytest 9.2.0**: Codex가 실제 API 소스를 작성했다. 승인한 21개 패키지 환경에서 라우트·스키마·입력 제약 검사 5개가 읽기 전용 Windows MXC 안에서 통과했다. 검증 영수증과 반영 바이트가 일치했다.
- **ASGI 통합**: 검토한 같은 코드와 승인한 패키지로 생성/조회·누락 인증·권한·없는 항목·잘못된 입력의 TestClient 검사 5개가 별도 로컬 환경에서 통과했다. 이 실행은 OS 격리 검증이라고 주장하지 않는다.
- **Node 24.19.0 / TypeScript 7.0.2**: 승인 npm과 실제 tsc 컴파일이 MXC 안에서 통과했다. 실제 TypeScript 소스의 진행률 계약 3개도 통과했다. 루트 디렉터리 읽기 권한을 추가하지 않았으며 하위 Node도 승인 경로를 사용한다.
- **실제 서버 UI**: 원장→인증된 로컬 서버→Edge로 27개 검사 통과. snapshot 주입 없음, 브라우저 오류 0. 파일 변경 SHA 거부, 실제 활동 갱신, 320·390px에서 워크플로우·작업 지도·타임라인 및 상세 패널을 확인했다.

## 회귀·빌드

**최종 전체 회귀: 424개 중 418개 통과·6개 환경 생략, 오류/실패 0개, 403.472초.** 실제 Windows 격리 CLI와 선택적 PDF 판독기를 활성화한 고정 소스 검사다. 생략 6개는 Linux 전용 프로세스 수명 검사 4개와 이 호스트의 링크 생성 권한/별칭 환경 검사 2개다.

- 프론트엔드 상태 검사 45개, 브라우저 회귀 93개 통과. TypeScript 검사·사이트 빌드·UI 번들 출처/해시 검사 통과.
- PDF 렌더러 14개, 보존 정리 15개 회귀 통과. 실제 Poppler와 Windows 디렉터리 접합점 검사를 포함한다.
- 기존 QA→수정→재검증 자동 진행 회귀 통과. 호스트 보고와 감독자 검증의 출처를 구분한다.

출시 준비 중 Windows·Python 3.10의 `Path.is_junction` API 부재 조건에서 실제 폴더 접합점 검사를 추가했다. reparse 속성으로 경계를 확인하도록 보완했으며 보안·작업자 회귀 23개가 모두 통과했다. 이 추가 변경과 새 버전 메타데이터는 원격 CI의 Python 3.10·3.12 / Linux·Windows 매트릭스에서 재검증한다.

## 관제 조회 부하 측정

같은 1MiB 합성 근거 파일을 공유하는 50·200·1000개 작업, 워밍업 후 각 20회. 전체 회귀가 동시에 실행 중인 로컬 Windows 측정이며 운영 용량 보증이나 고객 프로젝트 성능 측정은 아니다. p95는 20개 측정의 정렬된 19번째 값이다. 잠금 시간은 읽기 잠금 진입까지의 측정값이다.

요청당 공용 파일을 한 번 읽었고 다른 요청에서는 다시 검사했다. 외부 편집이 lifecycle revision 없이 발생해도 다음 요청에서 새 해시를 읽는 회귀를 통과했다. 작업 원장 전체를 읽고 잠금 안에서 스냅샷을 구성하는 구조는 유지하므로 더 큰 규모에는 추가 설계가 필요하다.

## 남는 지원 범위

- Windows 네트워크 차단은 asyncio의 내부 TCP 채널도 막는다. 등록 Python 검증은 이를 빠르게 환경 오류로 끝내고 자동 코드 수정으로 넘기지 않는다. ASGI 통합은 지원되는 별도 신뢰 환경에서 검증하고 범위를 표시한다.
- 토큰·비용 예산은 보고값으로 다음 작업을 제한한다. 이미 진행 중인 모델 요청의 청구 상한을 보장하지 않는다. 사용량이 미보고되면 표시하고 정책에 따라 멈춘다.
- Linux 원격 CI에서 Node 자식의 status=0·실제 완료 marker와 함께 spawnSync EPERM·빈 stdout이 재현됐다. 캡처 파이프를 검증 근거로 사용하지 않고 표준 입출력 상속·감독 파일 로그·실제 시작/완료 근거로 확인한다. Node 내부 캡처 파이프를 요구하는 도구까지 지원을 보장하지 않는다. [동일 증상 보고](https://github.com/openai/codex/issues/18473)는 참고 자료이며 정확한 시스템콜 원인까지 확정한 것은 아니다.
- 로컬 CLI 실행기는 프로젝트별 순차 실행이다. 현재 앱의 native 위임과 별도 CLI의 병렬 스케줄러를 혼동하지 않는다.
- 비밀 탐지는 일반적인 자격 증명 보호이며 모든 개인/영업 정보를 완벽히 식별하는 DLP가 아니다. 원시 로그와 사본은 비공개다.
- 렌더 영수증은 PDF→페이지의 실제 실행 근거다. 사용자 제공 DOCX/PPTX→PDF 제작 계보와 내용·디자인 검수 주장은 별도로 표시한다.
- 이번 실제 실행은 Windows에서 확인했다. Linux 프로세스 수명 전용 검사와 권한이 필요한 심볼릭 링크 검사는 환경에 따라 생략되며 새 변경을 모든 OS에서 검증했다고 주장하지 않는다.

운영 인터페이스와 정책은 [자동 실행 안내](AUTOMATIC-EXECUTION.md)를 따른다. 이 문서는 출시 전 검증 기록이다. 공개 배포 상태와 배포 파일은 [beta.5 릴리스](https://github.com/Agics-hsjeong/project-lifecycle-agent/releases/tag/v2.0.0-beta.5)에서 확인한다. 운영 고객 적용은 이 검증에 포함하지 않는다.
