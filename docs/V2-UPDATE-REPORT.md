# v2 업데이트·폴더 이동 분석 결과

기준일: 2026-11-03 · 로컬 검증 버전: **2.0.0-beta.1**

## 폴더 이동 분석

이동한 작업 폴더에서 기존 v2 알파 소스와 분석 문서를 확인했다. Git fsck에서 손상 객체는 발견되지 않았다. 기존 알파 87개 테스트도 새 경로에서 직접 통과했다. 이전에 반영만 되고 커밋되지 않았던 v2 작업을 이번 변경에 포함한다. 고객 프로젝트·참고 원본·기존 출력은 새 기본형으로 교체하지 않았다.

현재 채팅에 남아 있는 이전 I: 작업 공간 권한 정보와 앱에 등록된 새 D: 프로젝트 경로는 구분한다. 새 채팅에서는 이동한 프로젝트 폴더를 열고 실제 경로·설치 버전을 확인한다.

## 이번 보강

- 기존 프로젝트의 이행 미리보기·최신 revision/관리 파일 해시 확인·관리정보 백업·충돌 시 중단·직후 되돌리기.
- doctor의 실제 플러그인·프로젝트 경로, 관리 버전 차이, 기본형 버전·필수 파일·패키지 해시 검사.
- 플러그인·기본형·README·구현 안내·웹·PDF 버전 일치 검사와 CI 연결.
- v2 스킬·웹 사용 가이드·14페이지 사용자 매뉴얼 갱신.

이행 백업은 변경하는 project.json만 포함한다. 고객 코드·산출물 전체 백업은 별도이며, 사용자 프로젝트를 이번 검증의 가상 자료로 사용하지 않았다.

## 검증 결과

- 전체 99개 테스트 통과 (69.923초). 로그: .test-output/v2-beta-tests.log.
- 공식 스킬 형식 검사, Claude Code 2.1.300의 marketplace·plugin strict 검사 통과.
- 웹 프로덕션 빌드: HTML 16페이지, 내부 링크·자산 665건 통과.
- 매뉴얼: 14페이지·13개 북마크·전 페이지 버전 확인, 전체 렌더링과 접촉 시트·변경 페이지 시각 검수.
- ZIP: 원본과 일치하는 허용 파일 94개와 PACKAGE.json. 파일별 SHA256 일치·고객 자료 제외 확인.

## 실제 설치 결과

Codex와 Claude Code의 기존 사용자 설치를 공식 명령으로 0.5.1에서 2.0.0-beta.1로 갱신했다. 설치 ID와 스킬 이름은 그대로 유지했다. 원시 캐시 파일을 직접 편집하지 않았다.

두 호스트 모두 실제 설치 캐시의 doctor가 ready=true·package_integrity=true를 반환했다. 각 설치본으로 SI 11단계·제품 6단계·API 9단계·유지보수 6단계를 생성하고 가상 RFP 등록을 확인했다. 실제 요약 파일 작성·실행 완료·다른 호스트의 재개·폴더 이동 후 재개·로컬 현황 생성이 통과했다. 상세 결과: .test-output/v2-installed-hosts.json.

이번 컴퓨터의 marketplace는 저장소 dist/local-marketplace/project-lifecycle-agent에 풀어 둔 검증 배포본을 사용한다. 이 경로를 옮기거나 삭제하면 업데이트 소스를 다시 등록해야 한다. 기존 GitHub 소스는 두 호스트의 설치 전 기록에 보관했다. 실제 설치 캐시는 별도로 유지된다.

새 Codex 채팅·Claude Code 세션에서 업데이트한 스킬을 사용한다. “이 프로젝트의 실제 경로와 설치 버전을 확인하고, v2 이행 미리보기를 정리한 뒤 적용해줘”라고 요청할 수 있다.

## 공개 범위·남은 한계

GitHub push·태그·Release·공개 사이트 배포는 수행하지 않았다. 로컬 사용자 설치와 공개 main의 버전은 다를 수 있다. 고객 프로젝트의 일괄 이행·과거 승인 재작성·드라이브 백업/복구도 수행하지 않았다.

위 호스트 검증은 설치된 엔진의 실행·파일·상태 연동에 관한 것이다. 두 모델의 자동 스킬 선택이나 다양한 고객 Word/PowerPoint 템플릿의 의미·디자인 품질을 자동 인증하지 않는다. 실제 제안 작성에서는 로딩한 제작 도구로 전체 출력과 사실·스타일을 검수한다.
