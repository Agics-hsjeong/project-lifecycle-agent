# 자연어로 운영하는 관리 엔진

0.3.0부터 에이전트가 프로젝트를 조회하고 원장·검토·단계를 실제 관리합니다. 사용자는 RFP·목표·결정을 전달합니다. 실행 명령과 JSON 작성은 에이전트가 처리합니다.

## 실제 업무 예

1. 작업할 고객 폴더에서 “이 RFP로 외주 사업을 시작하고 요구사항과 고객 질문을 정리해줘”라고 요청합니다. 에이전트가 환경 점검 → 생성 → 원본 보존·추출 → 실제 내용 분석 → 사업 검토서·원장·인수인계 작성을 수행합니다.
2. “고객 답변을 반영해서 제안서를 작성해줘”라고 요청합니다. 신규 자료를 버전별로 등록하고 범위 영향과 질문을 정리합니다. 제안 초안을 작성할 수 있으며, 현재 단계의 공식 전환에는 실제 검토 결정이 필요합니다.
3. “검토했고 이 범위로 제안 진행을 승인해. 검토자는 김담당이야”처럼 실제 결정을 전달합니다. 에이전트가 대화/문서 근거를 파일로 남기고 검토를 기록한 뒤 다음 단계로 이동합니다. 이미 전달한 결정을 반복해서 묻지 않습니다.
4. 승인 이후 RFP나 범위가 바뀌면 다음 단계 이동 전에 영향을 받은 검토를 다시 확인합니다. 필요하면 CR과 근거를 남겨 이전 단계로 돌아갑니다. 기록을 지워 과거 결과를 바꾸지 않습니다.
5. Claude Code에서 하던 작업을 Codex로 이어갈 때 같은 고객 프로젝트 폴더를 엽니다. 에이전트가 현재 단계·문제·파일·테스트 결과·다음 행동을 읽고 진행합니다.

## 엔진과 호스트의 책임

| 엔진이 검사·기록 | 호스트 에이전트가 수행 |
| --- | --- |
| 입력 원본·해시·추출 상태 | RFP 의미 분석·표/도형 대조·고객 질문 |
| ID·원장 관계·실제 파일 경로 | 제안·기획·설계·UI·코드 작성 |
| 검토 시점의 범위·파일 해시 | 검토 결정의 실제 근거 확인 |
| 단계 순서·이전 단계 검토 유효성 | 연결 도구로 테스트·Git·배포 실행 |
| 잠금·변경 충돌·복구 기록 | 실제 실행 결과·미실행·다음 행동 기록 |

파일 존재·해시 검사는 내용의 정확성이나 실행 성공을 보장하지 않습니다. 검토 기록은 인증/전자서명이 아닙니다. 고객 자료를 공개 저장소에 올리거나 별도 서버로 보내는 기능은 없습니다. 상시 실행·일정 실행·자동 배포 권한은 호스트에서 별도로 제공해야 합니다.

## 0.2 프로젝트에 적용

기존 프로젝트 폴더와 파일을 보존하고 새 플러그인으로 이어갈 수 있습니다. schema_version=1과 기존 원장 필수 열을 유지합니다. 추가 열·열 순서를 보존합니다. 새 engine은 처음 변경할 때 state/를 생성하며 기존 문서·템플릿을 덮어쓰지 않습니다.

과거 reviews.csv만 있는 승인은 일반 check에서 읽히지만, advance에는 스냅샷이 필요합니다. 에이전트가 원래 승인 문서와 현재 결과를 대조해 사용자 권한 안에서 재확인하고 review로 기록해야 합니다. 과거 승인 날짜로 스냅샷을 만들어 넣지 않습니다. 원본이 manifest에 없다면 실제 파일을 ingest로 등록합니다. 새 자료 등록은 이전 검토의 입력 변경으로 감지됩니다.

starter_version은 생성 시 기본형 버전입니다. 기존 고객 프로젝트의 버전을 새 플러그인 버전으로 일괄 바꾸지 않습니다. AGENTS/CLAUDE와 회사 규칙 변경은 차이를 검토해 필요한 부분만 반영합니다.

## 중단과 복구

에이전트의 관리 명령은 쓰기 잠금과 변경 전 데이터를 사용합니다. 보통 오류는 자동으로 이전 상태로 되돌아갑니다. 비정상 종료로 pending.json이 남으면 다음 쓰기를 차단하고 recover로 복구합니다. 살아 있는 프로세스의 잠금은 해제하지 않습니다. 기록 이후 별도로 편집한 파일이 있으면 복구를 중단해 그 파일을 보존합니다.

이 기능은 엔진의 관리 파일 갱신에 적용됩니다. 편집기에서 작성하는 코드·문서 전체를 트랜잭션으로 묶지는 않습니다. 고객 프로젝트 저장소의 Git과 정기 백업도 함께 사용합니다.

## 배포 패키지

허용된 코드·양식·스킬·문서만 ZIP으로 묶으며 projects/, .test-output/, 고객 자료를 포함하지 않습니다. 연결된 파일/폴더는 거부합니다. ZIP에는 파일별 해시 목록 PACKAGE.json이 포함됩니다. 동일한 입력 파일은 동일한 ZIP을 생성합니다. 파일 내용이 운영체제에 따라 바뀌지 않도록 저장소의 줄바꿈 정책을 따릅니다.
