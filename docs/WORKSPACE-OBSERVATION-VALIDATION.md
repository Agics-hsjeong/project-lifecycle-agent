# 관찰형 워크스페이스 검증

2026-11-19, Windows / Asia/Seoul. 사용자의 후속 요구에 따라 관제를 승인 입력 화면에서 **역할별 실행을 관찰하는 화면**으로 전환했다. 미배포 소스 작업본이며 공개 사이트·플러그인 캐시를 교체하지 않았다.

## 현재 사용자 흐름

현재 Codex·Claude Code 대화에서 작업을 요청하고 질문·방향 변경·필요한 판단을 전달한다. 역할 작업자는 구현·독립 검토·수정을 이어간다. 관제는 진행 중·대기 중·완료, 실제 담당자·행동·경과 시간·검증 결과를 보여준다. 내부 작업마다 검토자 이름이나 수정 프롬프트를 입력하는 UI는 제거했다.

새 기본 연결은 현재 호스트의 실제 활동 보고다. 이 보고를 연결하지 않은 외부 채팅·도구 내역을 자동 수집한다고 주장하지 않는다. 별도 로컬 CLI 실행기는 선택적으로 사용하며 실제 native 공개 tool/action 이벤트를 실행 중 전달한다. 숨은 추론과 원시 인자는 공개하지 않는다.

## 실제 모델 E2E

Codex CLI 0.170.0, Claude Code 2.1.327을 기존 로그인으로 실행했다. 고객 자료 없는 두 합성 프로젝트를 실제 엔진과 HTTP 관제에 연결했다. 테스트에는 기존 구현의 의도된 공백 문자열 검증 결함을 넣고, 독립 QA가 반례를 작성하도록 했다.

1. 사람 게이트와 승인 결정이 없는 상태에서 QA를 시작했다.
2. QA가 실제 반례를 생성하고 감독 프로세스의 검증에서 nonzero를 확인했다.
3. 실제 산출물 해시에 연결된 `changes_requested` 검토를 기록했다.
4. 보호된 QA 반례와 실패 로그를 원 개발자에게 자동 전달하고 같은 쓰기 범위로 수정했다.
5. 감독자가 기존 검사와 보호된 반례를 실행한 후 독립 QA를 새 세대로 다시 실행했다.
6. 실제 `passed` 검토와 완료 영수증을 기록했다. 실패 명령·반례·원본 RFP를 보존했고 사람 승인 결정은 생성하지 않았다.

두 호스트 모두 QA → 개발 수정 → QA의 실제 세 프로세스가 실행됐다. 첫 네이티브 실행 전에 발견한 합성 기준 테스트 파일 누락은 진단 이력을 보존해 보완했으며, 첫 QA 시작 이후 수정·재검증을 수동 디스패치하지 않았다.

실행기 연결과 실제 모델 작업을 구분했다. live 표시에는 실제 running runner와 자식 PID 또는 신선한 실제 호스트 보고가 필요하다. 마지막 상태만 running이고 새 활동 근거가 없으면 활동 확인 필요로 표시한다. 경과 시간과 작업 완료 비율을 임의의 모델 퍼센트로 바꾸지 않는다.

Windows 기본 Temp 사본은 생성 파일의 소유자 전용 상속 ACL로 감독자가 읽지 못했다. 사본을 고객 프로젝트 바깥 `.ieum-runtime/<project>/jobs`로 변경해 실제 파일 읽기·검증·반영 성공을 확인했다. ACL과 native 샌드박스 정책은 완화하지 않았고 이전 실패 사본은 보존했다.

## 근거와 범위

로컬 비공개 근거는 `.test-output/observation-native/`에 있다. `full-regression.log`, `native-observation-report.json`, `observer-browser-report.json`, 각 프로젝트의 감독 영수증과 실행 사본에 실제 결과를 남겼다. 사용자 체험 근거는 `.test-output/workspace-user-trial/`에 있다. 런타임 토큰과 고객·테스트 사본은 배포 목록에서 제외한다.

작업 환경은 Python 표준 라이브러리의 작은 합성 프로젝트다. 모든 기술 스택·외부 연동·운영 배포를 검증한 것은 아니다. 모바일은 Edge headless 너비 에뮬레이션이며 실기기 검증이나 접근성 인증은 아니다. 현재 호스트의 native 역할 연결은 도구와 실제 보고를 필요로 하며, 이번 새 자동 수정 모델 E2E는 별도 native CLI 실행기로 검증했다.

## 2026-11-21 · 심층 검토 후 안정화

심층 검토의 10개 확정 결함을 수정했다. OS 격리 검증, 수신 후 준비 실패와 고아 수신 복구, 전체 프로세스 종료·입력 전송 및 최종 활동 수신 중 취소, 원본·추출문 무결성, PPTX/HWPX 순서·개수 검사, 관제 응답 역전·파일 Diff 갱신·잘못된 snapshot 보호를 포함한다. 추가로 실제 재현한 Windows 확장 경로 접두사·잠금 삭제 경합·종료 핸들 오인·긴 검증 실행 파일 경로도 수정했다.

- 영구 Node 40개와 프로덕션 Edge 브라우저 회귀 42개 통과. 브라우저는 응답 역전·취소·시간 초과·Diff SHA·잘못된 입력·감독 상태·409 원장 갱신 대기와 복구·모바일 상세를 포함한다. CI에 Node/브라우저 검사와 별도 실제 샌드박스 작업을 연결했다. 원격 CI를 이번 로컬 작업에서 실행했다고 주장하지 않는다.
