# 예시 템플릿 폴더 사용

예전에 만든 정성제안서와 발표자료를 새 사업의 스타일 기준으로 사용할 수 있습니다. 자료를 프로젝트별 또는 회사 공통 폴더에 넣고 자연어로 요청하면 됩니다. 일상적인 등록·분석·기록 명령은 에이전트가 실행합니다.

## 파일을 넣을 위치

프로젝트별 자료:

```text
<고객 프로젝트>/templates/qualitative/    정성제안서 DOCX/DOTX·PDF·HWP/HWPX·이미지
<고객 프로젝트>/templates/presentation/   발표자료 PPTX/POTX·PDF·이미지
```

회사 공통 자료:

```text
<작업 공간>/reference-templates/qualitative/
<작업 공간>/reference-templates/presentation/
```

같은 폴더에 여러 예시와 스타일을 넣을 수 있습니다. 실제 경로가 다른 곳이면 그 폴더를 알려주면 됩니다. 회사 공통 폴더는 고객 프로젝트로 필요한 자료를 등록해 사용합니다. 원본을 수정하거나 공개 플러그인에 올리지 않습니다. 이 저장소의 reference-templates/는 .gitignore와 배포 허용 목록으로 제외합니다.

## 요청 예

> 회사 참고 템플릿 폴더를 분석해줘. 정성제안서는 A 문서의 표·문체·목차 전개를, 발표자료는 B 발표의 마스터·배치·도식·설득 흐름을 기준으로 이번 RFP 자료를 만들어줘. 이전 고객 정보는 교체하고 실제 생성본을 비교 검수해줘.

예시가 하나이면 해당 자료를 선택합니다. 여러 자료이고 지정한 기준이 불명확하면 에이전트가 후보를 정리하고 필요한 선택을 확인합니다. 기존 선택은 새 파일이 들어왔다고 자동으로 바뀌지 않습니다.

## 실제 처리

1. 원본을 TPL-ID와 SHA256으로 보존합니다. 같은 파일은 중복 등록하지 않고 변경된 버전은 따로 보존합니다.
2. DOCX/PPTX의 편집 구조를 자동 관측합니다. 호스트가 실제 화면을 읽고 표지·본문·표·도식·증빙 등 대표 패턴과 문체·작성 노하우를 분석합니다.
3. 스타일·레이아웃·문체·재사용 패턴·이전 사업 정보 교체 규칙을 파일로 기록합니다. 색상만 흉내 내는 방식으로 끝내지 않습니다.
4. 선택한 원본의 편집 구조를 활용해 새 문서·슬라이드를 제작합니다. 작업 사본에는 과거 내용이 있으므로 고객명·실적·가격·수치·노트·주석·메타데이터 등을 교체·검수합니다.
5. 새 결과 전체를 렌더링하고 원본의 대응 패턴과 비교합니다. 차이와 이유, 남은 문제, 검수 범위를 기록합니다.
6. 제안 승인 시 원본·분석·실제 제출 파일·비교 근거를 묶습니다. 검수 후 바뀌면 다시 확인해야 합니다.

분석·선택·비교 기록은 templates/manifest.json, selection.json, profiles/, analysis/, output-checks.json에 저장됩니다. 에이전트가 관리하며 사용자가 JSON을 편집할 필요가 없습니다.

## 지원 범위

| 자료 | 활용 방식 |
| --- | --- |
| DOCX/PPTX | 기본 구조 관측, 원본을 보존한 편집 작업 사본, 실제 제작 도구에서 스타일·마스터/레이아웃 활용 |
| DOTX/POTX | 구조 관측과 스타일 기준. 최종 편집본으로의 변환은 호스트 도구에서 수행 |
| PDF/HWP/HWPX/이미지 | 호스트의 문서·OCR·시각 도구로 분석한 뒤 재구성. 편집 가능한 원본과 동일한 복원을 보장하지 않음 |

자동 구조 분석은 문서 렌더러나 디자인 유사도 판정기가 아닙니다. 스타일 재현의 품질은 실제 예시와 생성본을 보며 검증해야 합니다. 원본의 규칙을 추출해 파일로 재사용하며 모델을 별도로 학습시키는 기능은 아닙니다. 읽지 못한 자료·미실행 렌더링은 완료로 표시하지 않습니다.

기존 0.4 프로젝트에는 원장/문서를 덮어쓰지 않고 참고 폴더를 추가할 수 있습니다. 제안 패키지가 없는 더 오래된 프로젝트에는 제안 패키지도 먼저 추가합니다. 기존 고객 규칙은 보존하고 새 스킬의 참고자료 작업 절차를 적용합니다.
