# 역할 자동 실행과 활동 관찰 · beta.4 이후

사용자는 Codex·Claude Code에 “이거 해줘”라고 요청한다. 주 에이전트가 실제 역할 작업자를 선택하고 구현·독립 검토·수정을 이어간다. 관제 화면은 **누가, 무엇을, 언제 하고 있으며 얼마나 끝났는지** 보여준다. 내부 작업마다 별도의 사람 승인 폼을 채우게 하지 않는다.

## 사용자 요청 예시

> 이음으로 문의 기능을 구현해줘. 필요한 역할끼리 검토하고 고쳐서 테스트까지 끝내고, 현재 진행 상황을 관제에서 보여줘.

방향 변경과 질문은 같은 AI 대화에서 전달한다. 관제에서는 진행·대기·완료, 역할 활동, 실제 행동·검증 결과와 산출물을 확인한다. 사업 결정·외부 공개·배포 등 별도 권한이 필요한 판단은 기존 대화와 호스트 승인 흐름에서 처리한다.

## 호스트에서 직접 진행하기

현재 AI 호스트가 주 실행자다. 이음 스킬은 실제 프로젝트를 확인하고 필요한 역할의 native Agent/Task/spawn을 실행한다. 관제 연결이 있으면 호스트 훅과 관측기가 세션별 실제 작업자 시작·종료·공개 도구 행동을 수집한다. 주 에이전트는 TASK와 역할의 위임 연결을 준비하고, `workspace-activity`로 검토·전달 같은 보충 활동을 기록할 수 있다. TASK/RUN의 완료는 기존 엔진의 근거·검증 규칙으로 기록한다.

활동 보고는 대화나 도구를 실제 수행한 호스트의 보고다. 연결하지 않은 외부 대화 전체를 자동 수집하거나 숨은 추론을 표시하는 기능이 아니다. 사용자가 추가 명령을 외우지 않도록 에이전트가 기록을 처리한다. 새 프로젝트 체계를 일반적인 코딩 요청에 강제하지 않는다.

```text
python tools/starter.py workspace-serve <project> --open
python tools/starter.py workspace-activity <project> --file <activity.json> --json
python tools/starter.py workspace-review <project> --file <review.json> --json
```

관찰 서버는 모델 실행과 별개로 유지한다. 활동에는 실제 host/provider, 작업자 ID, 역할, TASK ID, 실행한 행동과 결과만 넣는다. 내부 추론·원시 명령 인자·자격 증명은 넣지 않는다. 실행 상태는 실제 파일·테스트·호스트 결과로 갱신한다.

## 선택적인 로컬 실행기

현재 호스트 밖에서 준비된 작업을 이어가도록 요청한 경우에는 로그인된 별도 네이티브 CLI 프로세스를 연결한다.

```text
python tools/starter.py workspace-serve <project> --provider codex --open
python tools/starter.py workspace-serve <project> --provider claude --open
```

서버가 이미 있으면 `workspace-runner <project> --provider codex|claude`로 실행기만 붙인다. 기본은 현재 사용하는 AI 또는 사용자가 지정한 호스트다. 한 프로젝트에는 하나의 실행기만 연결하고 현재 앱 작업과 같은 TASK를 중복 수행하지 않는다. `--executable`로 검증한 CLI 설치를 선택할 수 있다.

실행기는 준비된 작업을 선후 관계에 따라 순차 처리한다. 모델 시작·공개 tool/action·파일 행동·검증 그룹의 시작과 결과·후속 역할 인계를 활동으로 보고한다. 전체 완료 작업 수와 실제 경과 시간을 표시하며 임의의 모델 진행률을 만들지 않는다. native JSONL의 숨은 추론이나 원시 인자를 UI로 전달하지 않는다.

CLI에는 기존 로그인과 실제 사용 한도가 적용된다. 컴퓨터와 실행기가 꺼지면 처리는 이어지지 않는다. 이 버전은 프로젝트당 순차 실행기이며 여러 역할을 동시에 실행하는 별도 병렬 스케줄러는 아니다. 현재 앱의 native 역할 위임은 호스트가 지원하는 범위에서 동작한다.

## 검토와 자동 수정

독립 QA/리뷰는 사람 승인을 대신 기록하지 않고 `passed` 또는 `changes_requested`와 실제 근거를 남긴다. 확인된 코드 결함은 기존 개발자의 허용 경로와 수용 기준 안에서 수정하고 다시 검증한다. QA가 만든 반례와 검증 근거를 개발자가 지워서 통과할 수 없도록 감독자가 보호한다. 같은 원인의 자동 수정은 제한된 횟수로 수행하고 계속 실패하면 원인과 해결 조건을 보고한다.

인증·권한·프로세스 중단·외부 장애를 코드 결함으로 해석해 무한 재시도하지 않는다. 사람이 판단할 질문은 현재 AI 대화에서 설명하고 관제에는 상태와 이유를 표시한다. AI 검토를 사람 승인·수주·운영 배포 권한으로 바꾸지 않는다.

이전의 명시적 관제 사람 게이트는 기본값과 이력을 보존한다. 사용자가 내부 검토 자동화를 요청하면 `workspace-configure`에서 해당 게이트의 `required:false`를 명시한다. 이후 관찰 대상으로만 표시하며 가짜 사람 승인 기록을 만들지 않는다. 새 작업마다 관제 게이트를 임의 생성하지 않는다.

## 작업 범위와 검증

별도 실행기의 자동 수행은 명시한 프로젝트 정책 `policy.auto_run:true`로 활성화한다. 현재 호스트가 직접 수행하는 관찰 연결에서는 같은 작업을 중복 큐 실행하지 않는다.

로컬 실행 작업에는 신뢰하는 `workspace-configure` 경로에서 `execution.instruction`, `allowed_paths`, `expected_outputs`, `verification_commands`를 등록한다. 검증 명령은 셸 문자열이 아닌 argv 배열이다. 브라우저 조회 API는 실행 파일이나 명령을 등록하지 않는다.

모델은 격리 사본에서 담당 파일만 변경한다. 감독자가 사본에서 독립 검증을 실행하고 원본 입력·계약·파일 해시를 확인한 후 허용 파일만 반영한다. 관리 기록과 비밀 파일은 모델이 변경하지 못한다. QA 반례·승인 이력·감독 영수증은 보호한다. Codex native 샌드박스와 자동 승인 검토를 유지하고 Claude 작업자는 허용된 파일 도구만 사용한다.

기본 사본은 고객 프로젝트 밖 `../.ieum-runtime/<project>/jobs/`에 보관한다. Windows 임시 폴더의 소유자 전용 상속 ACL로 감독자가 출력물을 읽지 못하는 문제를 피하며 ACL이나 샌드박스를 완화하지 않는다. 이 폴더는 비공개 로컬 런타임 자료이고 커밋·배포 대상이 아니다. 이전 실패 사본은 보존한다.

`.venv`, `node_modules`, 자격 증명은 사본에 복사하지 않는다. 외부 의존성이 필요한 프로젝트는 사용할 검증 런타임을 먼저 준비해야 한다. 모델이 임의로 패키지를 설치하지 않는다. Python 표준 라이브러리 E2E를 여러 기술 스택·클라우드 배포의 검증으로 확대해 설명하지 않는다.

## 기록과 복구

`state/workspace-native.json`은 세션별 실제 작업자·위임 연결·정규화한 호스트 이벤트다. `state/workspace-activity.json`은 제한된 공개 활동 타임라인이다. `state/workspace-runtime.json`은 실제 실행기·PID·heartbeat, `state/workspace.json`은 작업 연결·대기열·검토·기존 결정 이력이다. 짧은 활동 보고가 사업 원장의 revision을 계속 바꾸지 않도록 분리한다. `reports/runner/`에는 독립 검증과 완료·실패 영수증을 기록한다. 사용량은 실제 보고값만 합산하며 미제공 값은 미집계다.

정상 중지는 소유 실행기의 stop/Ctrl+C로 수행하고 해당 자식만 종료한다. 살아 있는 중복 실행기를 거절하며 비정상 종료된 이전 작업은 확인 없이 자동 중복 실행하지 않는다. 원본이 바뀌면 덮어쓰지 않고 새 기준으로 조율한다.

## 2026-11-21 안정화

작업 수신 전 소유권 의도를 기록하며 준비 실패도 실제 실패 영수증으로 끝낸다. 소유 프로세스가 종료됐다는 기록이 있는 고아 수신만 복구한다. 실패 모델 작업을 임의로 중복 실행하지 않는다. 실행기 시작 충돌은 제한된 지수 대기로 재시도하고, HTTP 조회와 `host.supervisor` 및 실제 `runner_connected`를 별도로 표시한다.

모델과 검증 명령의 전체 프로세스 트리를 소유한다. Windows는 시작 전 Job Object에 연결하고 정상 종료·중지·시간 초과 시 남은 자식도 정리한다. 입력 pipe 전송도 같은 중단·제한 시간 안에서 감시한다. 종료됐지만 핸들이 남은 프로세스를 실행 중으로 오인하지 않는다.

독립 검증은 Codex sandbox CLI를 로컬 격리 도구로 사용한다. 모델 API나 Codex 모델 인증을 사용하는 검증이 아니다. 실행기 provider가 Claude여도 이 검증 도구는 별도로 필요하다. `--verification-executable`로 CLI 실행 파일 또는 JavaScript 경로를 연결할 수 있다. Windows는 MXC를 요구하며 읽기 기본 거부·최소 런타임 읽기·검증 소스 읽기 전용·전용 scratch 쓰기·네트워크 차단을 적용한다. 호스트 관리 정책을 포함하고 사용할 수 없으면 실패로 표시한다. 비격리 fallback은 없다.

Windows의 사용자 전용 Python ACL을 바꾸지 않는다. 공개 Python 실행 파일·표준 라이브러리·라이선스를 작업별 감독 런타임에 복사하고 사본 밖의 읽기 전용 경로로 연결한다. 설치된 site-packages·자격 증명은 복사하지 않는다. 외부 라이브러리나 네트워크가 필요한 검증은 신뢰하는 런타임과 정책을 준비해야 하며 이 기본 검증 범위로 성공을 보장하지 않는다. 환경 변수는 운영체제·실행에 필요한 경로만 전달한다.

검증용 공개 런타임은 긴 작업 경로에서도 Windows 실행 파일 경로 제한에 걸리지 않도록 짧은 소유 OS 임시 경로에 만들며, 작업 사본 밖 읽기 전용으로 연결한다. 검증 후에는 소유 경로·링크 여부를 확인해 이 런타임만 정리한다. 모델이 작성한 산출물은 기존 고객 밖 작업 사본에 그대로 보존한다.


## 실제 실행 연결과 범위 — 2.0.0-beta.6

기본 사용은 AI 대화의 자연어 요청이다. 관제 사용자는 ID·JSON을 입력하지 않는다. 에이전트는 위임 전에 실제 TASK·역할·provider·session을 연결하고 호스트 이벤트의 native ID를 결합한다. 같은 역할만 보고 TASK를 추정하지 않으며 모호한 호출은 미연결로 남긴다. 호스트가 변경된 플러그인 훅의 신뢰 확인을 표시하면 사용자가 해당 UI에서 검토해야 한다. 이를 건너뛰거나 임의로 신뢰 설정을 바꾸지 않는다.

`runs.create`의 선택 필드 `bindings`는 `{ "STEP-001": "TASK-001" }`, `scope`는 `{ "id": "api-revision", "title": "API 수정", "supersedes": ["RUN-001"] }` 형식이다. RUN 생성·TASK 바인딩·범위 선언을 한 트랜잭션에 저장한다. 기존 5개 필수 필드 API는 그대로 지원한다. TASK의 이전 STEP은 결과·해시를 지우지 않고 대체 이력에 남는다. `workspace-configure.current_scope`에 실제 `task_ids`와 `title`을 지정하면 명시 범위를 선택하고 `null`이면 최근 RUN 기준으로 돌아간다. 실행 계획을 새로 선언하면 새 RUN이 최근 범위가 된다.

Snapshot의 `tasks`는 전체 비중복 작업 목록, `current_scope.task_ids`는 현재 표시 범위다. `summary_counts`는 현재 범위, `all_summary_counts`는 전체 작업, `history_tasks`는 현재 범위 밖 작업이다. `history_runs`에는 대체된 STEP의 상태·현재 유효성·원본 영수증 해시도 남는다. `execution_scopes`는 독립 실행 선언을 보존한다. 유효성에 따라 최근 RUN을 건너뛰거나 실패 이력을 삭제하지 않는다.

각 작업의 `ledger_status`는 원장·무결성 검사 상태이고 `execution_state`는 호스트에서 관측한 실행 상태다. `native_agent_id`, `session_id`, `runtime_source`와 활성 native ID를 함께 제공한다. native 종료는 `result_pending`일 수 있으며 검증 통과나 사람 승인을 생성하지 않는다. 완료·실패·변경됨 근거는 기존 엔진 규칙을 유지한다. 호스트 이벤트에는 정규화한 공개 메타데이터만 허용하고 원시 프롬프트·결과·추론·전사 경로는 받지 않는다.

TASK 생성·변경에서는 제목을 메타데이터에 함께 저장한다. 선택 필드 `title`을 명시할 수 있고 `next_action` 변경은 제목을 덮지 않는다. 구형 제목은 연결된 RUN·이전 미완료 기록으로 복원하며 조회는 기록을 쓰지 않는다.

## 강화된 검증과 관찰 — 2.0.0-beta.5

사용자는 Codex·Claude Code 대화에서 목표를 요청합니다. 에이전트가 필요한 역할, 선행 조건, 허용 파일과 검증 명령을 준비합니다. 관제에서 매 작업을 승인하거나 JSON을 입력할 필요는 없습니다. 실제 고객 결정·외부 제출은 대화에서 확인합니다. 기존 프로젝트에 사람이 설정한 게이트는 자동으로 삭제하지 않습니다.

코드 작업의 `verification_commands`는 비어 있을 수 없습니다. 감독자는 작업 컨텍스트·입력·검증 계획·후보 파일을 해시로 결속한 뒤 소스를 읽기 전용으로 검증합니다. 검증 뒤 바뀐 파일은 반영하지 않으며 검증한 고정 바이트만 전달합니다. `passed`는 등록된 검사의 성공을 뜻하며 모든 결함이 없다는 보증이 아닙니다. 문서만 만드는 작업은 `verification_mode: artifact_only`와 사유를 명시하며 코드 실행 검증 성공과 구분합니다.

`execution.input_paths`로 필요한 입력만 지정합니다. 미지정이면 작업의 입력·담당 파일·알려진 빌드 메타데이터를 추론하여 제한하며 프로젝트 전체를 복사하지 않습니다. 비밀 파일명과 탐지 가능한 자격 증명 내용은 복사·관제·산출물 다운로드에서 차단합니다. 생성 작업자도 프로젝트 밖 파일을 읽거나 쓰지 못하도록 제한합니다. Claude 생성 작업자는 실제 검증한 Claude Code 2.1.327 이상을 요구하며, 지원하지 않는 버전은 시작 전에 차단합니다. 이 탐지는 임의의 모든 민감정보를 식별하는 DLP 보증은 아닙니다. 원시 CLI 로그와 사본은 비공개 로컬 런타임으로 취급합니다.

### 실제 의존성을 사용하는 프로젝트

FastAPI·pytest·TypeScript 등 외부 의존성은 신뢰하는 환경에서 lockfile에 맞게 설치한 뒤 감독자가 등록합니다. 모델이 임의의 설치 스크립트를 검증 환경에서 실행하지 않습니다. 다음 명령은 사용자가 매번 입력하는 절차가 아니라 에이전트·운영자가 환경을 준비할 때 사용하는 인터페이스입니다.

```text
python -m tools.verification_runtime PROJECT --kind python --lockfile requirements.lock --packages APPROVED_SITE_PACKAGES
python -m tools.verification_runtime PROJECT --kind node --lockfile package-lock.json --packages APPROVED_NODE_MODULES --node NODE_EXECUTABLE --npm APPROVED_NPM_DIRECTORY
```

결과의 `runtime_ref`를 작업의 `execution.runtime_ref`에 연결합니다. 원본·후보 lockfile SHA와 등록 환경의 전체 파일 해시가 일치해야 합니다. 환경이 없거나 달라졌으면 모델에게 코드를 계속 고치게 하지 않고 환경 오류로 끝냅니다. Python 검증은 호스트 site-packages를 상속하지 않습니다. npm은 등록된 `run`·`test`만 사용하며 설치·네트워크 다운로드를 허용하지 않습니다. 소스는 읽기 전용이므로 빌드 산출물·캐시는 검증 scratch에 쓰도록 명령을 준비합니다. 등록 환경은 OS·아키텍처·Python 버전에 종속됩니다. Windows의 네트워크 차단 격리에서는 asyncio가 내부 TCP 채널을 사용하는 ASGI TestClient 검증을 지원하지 않습니다. 승인 Python 런타임은 이를 빠르게 환경 오류로 종료하며 코드 수정 루프로 넘기지 않습니다. API 스키마·순수 로직은 격리 검증하고, ASGI 통합은 별도 신뢰 환경에서 실행하여 그 범위를 명시합니다. 실제 HTTP 테스트를 실행하지 않고 통과로 기록하지 않습니다. Linux Codex 격리에서는 중첩 Node 작업의 캡처 파이프가 EPERM 또는 빈 출력을 만들 수 있습니다. 감독자의 파일 로그와 표준 입출력 상속을 사용하며, 캡처 파이프가 필요한 도구는 해당 환경에서 별도 호환성 검증이 필요합니다. 빈 로그나 종료 코드만으로 실제 검증 실행을 추정하지 않습니다. [관련 upstream 보고](https://github.com/openai/codex/issues/18473)를 참고하세요.

### 관제에서 확인할 것

- 데이터 연결, 현재 앱의 native 역할 실행, 별도 CLI 실행기를 구분합니다. 실제 heartbeat가 없는 연결을 실행 중이라고 표시하지 않습니다.
- 완료·진행·대기·차단·실패·제외를 별도로 셉니다. 제외는 완료가 아니며 적용 대상 분모에서 빠집니다. 임의의 모델 진행률은 만들지 않습니다.
- 검증 배지는 등록 검사 성공·문서 전용·미검증·실패·변경됨을 구분합니다.
- 사용량은 알려진 합계와 미보고 실행 수를 함께 표시합니다. 일부 보고만 받은 값을 전체 비용으로 표시하지 않습니다.
- 산출물은 등록된 파일 ID와 현재 SHA가 맞을 때만 인증된 로컬 경로로 받습니다. PDF·PNG·JPEG만 제한된 미리보기를 제공하며 HTML·SVG는 인라인 실행하지 않습니다.

`policy.limits`는 `max_tokens`, `max_cost_usd`, `max_seconds`, `unknown_usage: stop|warn`을 지원합니다. 토큰·비용은 보고 시점의 관측값으로 다음 작업 시작을 제한하므로 한 모델 요청의 청구 상한을 강제하는 기능은 아닙니다. 시간 제한은 모델·검증 전체의 누적 경과 시간에 적용합니다.

### 출력물 렌더링과 비공개 런타임 정리

`python -m tools.artifact_renderer PROJECT --pdf exports/result.pdf --source exports/result.docx`는 설치된 신뢰 가능한 Poppler로 PDF 전체 페이지를 PNG로 렌더링하고 파일·도구 해시를 기록합니다. 원본 DOCX/PPTX에서 PDF로 변환한 계보가 사용자 제공이면 `host_supplied_unverified`로 남습니다. 렌더링 사실과 내용·디자인 검수 주장을 혼동하지 않습니다. `artifact-review`의 `require_render_provenance:true`로 렌더 영수증이 필요한 검수를 지정할 수 있습니다.

`python -m tools.runtime_retention --help`로 비공개 작업 사본·원시 로그의 보존 정리를 준비할 수 있습니다. 기본은 미리보기이며 저장한 계획의 명시 적용만 삭제합니다. 실행 중인 큐·lease·프로세스, 바뀐 계획, 외부 링크는 거부합니다. 고객 원본·완성 산출물·프로젝트 이력·구조화 영수증·승인 의존성 캐시는 정리하지 않습니다. 자동 삭제는 기본으로 활성화되지 않습니다.
