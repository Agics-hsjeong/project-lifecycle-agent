# Codex·Claude 연결

v0.2부터는 [플러그인 설치·자연어 요청](PLUGIN.md)이 기본 사용 방식입니다. 아래 내용은 플러그인이 생성한 프로젝트의 지침 연결을 확인하거나 파일 기본형을 직접 쓰는 경우를 위한 안내입니다. 프로젝트 생성·원장 갱신·점검은 에이전트가 수행합니다.

확인일: 2026-10-15. 아래 지침은 프로젝트 파일 기반 연결이다. 두 제품 계정 간 연결이나 AI 간 자동 메시지 전송을 설정하지 않는다.

## Codex

생성된 프로젝트 폴더를 Codex의 작업 폴더로 연다. 프로젝트 루트의 AGENTS.md가 공통 진입 지침이다. 여기에 project.json, HANDOFF.md, process 문서를 읽도록 지정했다. 전역 지침이나 상위 폴더의 override가 있으면 함께 적용될 수 있으므로 새 세션에서 확인한다.

```text
적용 중인 지침 파일과 현재 프로젝트 경로를 알려줘.
project.json에서 프로젝트 이름과 단계를 읽고,
process/WORKFLOW.md에서 이번 단계의 산출물·완료 기준을 요약해줘.
```

지침 파일을 변경한 뒤에는 새 세션에서 로딩을 확인한다. 세부 문서 전부를 처음부터 자동으로 읽는다고 가정하지 않는다.

공식 근거: [OpenAI — AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

## Claude Code

같은 프로젝트 폴더에서 Claude Code를 연다. CLAUDE.md의 `@AGENTS.md` import가 공통 지침을 가져온다. 이렇게 하면 두 진입 파일에 업무 규칙을 중복 작성할 필요가 없다.

새 세션에서 `/context`로 메모리 파일을 확인하고 위와 동일한 확인 요청을 보낸다. 프로젝트·전역 설정에 따라 로딩이 달라질 수 있다.

공식 근거: [Anthropic — 프로젝트 메모리](https://code.claude.com/docs/en/memory).

## Claude 웹·앱 대화에서 사용

로컬 폴더 지침이 자동 적용된다고 가정하지 않는다. AGENTS.md, project.json, HANDOFF.md, 현재 단계 문서와 관련 입력 자료를 직접 첨부한다. `context` 명령의 출력도 붙여 넣는다. 민감 자료는 회사의 사용 정책과 해당 서비스 설정에 맞춰 제공한다.

대화에서 생성한 결과는 사람이 프로젝트 파일로 반영한다. 별도 파일 접근 도구가 연결되지 않았다면 로컬 파일이 자동 저장되지는 않는다.

## AI를 바꿔서 이어가기

1. 작업 중인 AI에게 HANDOFF.md와 원장 업데이트를 요청한다.
2. 코드가 있으면 변경 파일·브랜치·커밋·테스트 결과를 기록한다. 실행하지 않은 테스트는 미실행으로 표시한다.
3. 다음 AI가 같은 폴더 또는 같은 커밋의 복제본을 읽게 한다.
4. 다음 AI에게 인수인계 내용과 실제 파일의 일치 여부를 확인하게 한다.

같은 파일을 두 AI가 동시에 수정하지 않는다. 병행 작업은 명시적으로 요청한 경우에만 파일 범위를 나누고 브랜치 또는 별도 작업 디렉터리를 사용한다.
