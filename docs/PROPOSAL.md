# 정성제안서와 발표자료 운영

정성제안서와 발표자료는 각각 제작하고 서로의 범위·주장·수치를 대조합니다. RFP의 지정 목차·평가기준·제출 조건이 우선이며, 작성한 파일과 검토 결과를 제안 단계에 묶어 보존합니다.

| 산출물 | 다루는 내용 |
| --- | --- |
| 정성제안서 DEL-002 | 사업 이해, 전략·차별점, 구체적 수행·기술·조직·품질·보안·운영 방안, 실제 증빙 |
| 산정서 DEL-003 | 일정·공수·비용 가정과 산식, 인력·일정·범위 정합성 |
| 평가 대응 DEL-015 | 원문 평가항목·배점·REQ·주장/근거·제안서 절·발표 슬라이드 |
| 발표자료 DEL-016 | 청중·평가 관점의 스토리, 시각 구성, 발표 시간과 실제 PPTX/PDF |
| 대본·Q&A DEL-017 | 슬라이드별 대본·전환·시간, 예상 질문·근거 있는 답변·담당, 리허설 계획/결과 |
| 제출 점검 DEL-018 | 마감·파일명·형식·익명화·분량·서명/첨부, 최종 파일·시각 검수·제출 증거 |

사용자는 “이 RFP로 정성제안서와 발표자료, 대본·예상 Q&A까지 만들어줘”라고 요청합니다. 에이전트가 원문을 읽고 작성·디자인·파일 제작·검수·기록을 진행합니다. 페이지 제한이나 발표 시간이 없으면 확인 질문과 가정을 구분하며 원문에 없는 조건을 만들지 않습니다.

## 실제 파일 제작

Markdown은 초안·구성·관리 기록으로 사용합니다. 제출본은 지정된 DOCX/PDF/HWP/HWPX, 발표는 PPTX/PDF로 생성합니다. 호스트에 제공된 문서·발표 제작 도구와 해당 스킬을 사용합니다. 지원하지 않는 지정 형식은 확장자만 바꾸지 않고 제한과 미완료를 보고합니다. 실제 제출하지 않았다면 미제출로 기록합니다.

문서 전 페이지와 슬라이드 전체를 렌더링해 잘림·겹침·글꼴·표/그림·번호·익명화·페이지 제한을 확인합니다. 발표 대본 시간과 RFP 제한을 대조합니다. 전자서명·직인·외부 제출은 실제 권한과 지시에 따릅니다.

## 자동 점검

proposal/package.json에 평가 EVAL, 발표 SLIDE, 실제 제출 파일을 등록합니다. 엔진은 다음을 검사합니다.

- 평가항목의 원문 근거·정성제안서 대응 절·실제 주장 증거, 요구사항 ID 존재
- 평가항목과 슬라이드의 양방향 연결, 슬라이드별 핵심 메시지·대본·시각 구성·시간
- 발표 시간 합계와 제한, 계획된 슬라이드 수와 PPTX 실제 장수
- 제출 파일 존재와 기본 컨테이너 형식, 승인 뒤 제출본·증빙·설정 변경

이 검사는 제안서 내용의 충실성·배점 판단·실적 진위·시각 품질을 판정하는 모델 평가가 아닙니다. 실제 원문 대조·렌더링 검수·책임자 검토를 함께 수행합니다. PDF 장수나 HWP 내부 내용은 호스트 문서 도구에서 확인합니다.

발표가 없는 사업은 원문/합의 근거와 제외 사유를 기록하고 발표자료·대본을 적용 제외로 검토할 수 있습니다. 자체 서비스는 사업 실행안·투자/내부 피치로 조정합니다. 기존 프로젝트는 요청한 범위에서 에이전트가 proposal-setup으로 기능을 추가하며 고객 파일을 덮어쓰지 않습니다.
