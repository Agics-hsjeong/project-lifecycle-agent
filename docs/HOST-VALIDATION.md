# beta.2 호스트 실행 검증

검증일: 2026-11-19 (Asia/Seoul). 버전: 2.0.0-beta.2.

## 환경과 실제 요청

Windows 11 / Python 3.12.10에서 공식 Codex CLI 0.170.0과 Claude Code 2.1.327을 실행했다. 각각 로그인된 실제 계정을 사용했고, 모델·추론 설정은 기존 호스트 기본값을 상속했다. 검증 CLI는 배포 제외 임시 폴더에 준비했으며 전역 CLI·전역 권한 설정을 교체하지 않았다.

패키지 허용 목록으로 만든 ZIP을 Codex의 임시 로컬 marketplace에 설치하고 Claude Code에는 세션별 plugin-dir로 로딩했다. 고객 프로젝트에는 각각 Codex 역할 설정·Claude /ieum 별칭을 준비했다. 원본 고객 자료 없이 같은 가상 요구사항을 독립 폴더에서 사용했다.

사용자 요청은 다음과 같으며 팀·병렬·역할 이름을 추가하지 않았다.

```text
inputs/host-task.md를 읽고 문의 조회 기능을 구현해줘.
README 사용 예시와 자동화 테스트도 만들어서 실행하고,
구현 결과와 남은 문제를 정리해줘.
Python 표준 라이브러리만 사용하고 외부 서비스와 배포는 하지 마.
현재 프로젝트 폴더 밖 파일은 수정하지 마.
```

Codex는 `$ieum`, Claude Code는 `/ieum`으로 위 요청을 전달했다. 가상 프로젝트의 현재 단계는 테스트 준비 과정에서 implementation으로 설정했고 이를 실제 사업 승인으로 취급하지 않았다.

## 실제 제한과 해석

이 검증은 가상 로컬 Python 기능 한 건의 역할 실행·통합·재개에 대한 사례다. 18개 역할의 모든 전문 작업, 실제 회사 템플릿 문서 품질, 실제 운영 배포, 모든 OS·데스크톱 UI를 보증하지 않는다. 두 호스트의 단순 도움말과 읽기 전용 이어하기에서는 프로젝트 파일 변경이 없었다. Claude 단순 도움말에서는 하위 에이전트를 만들지 않았다. 다른 요청의 역할·수는 난이도·기존 산출물·호스트 기능에 따라 달라진다.

Codex 앱 번들 CLI 0.169.0-alpha.11.1의 첫 시도에서는 `registered Core launch requires an installed app` 오류가 발생했다. 공식 독립 CLI 0.170.0으로 재검증했고, 호스트가 허용하는 실행 승인·재시도 경로에서 작업을 완료했다. 샌드박스 우회 플래그나 전역 권한 해제는 사용하지 않았다. 데스크톱 UI에서의 새 플러그인 세션은 이번 CLI 검사와 구분한다. Claude의 비대화형 세션에서도 일부 셸 명령의 권한 거부가 있었으나 허용된 파일/명령 도구로 대체한 뒤 최종 파일·로그를 확인했다. 모든 환경에서 권한 질문이나 도구 오류가 사라졌다는 의미는 아니다.

원시 실행 이벤트·테스트·해시·화면 자료는 로컬 `.test-output/host-smoke/`와 `.test-output/role-agents/`에 보존한다. 로그인 정보·계정 식별자·전체 세션 로그·실제 고객 자료는 공개 패키지에 포함하지 않는다. 공개 배포 결과는 해당 GitHub 태그·Actions·Pages에서 확인한다.
