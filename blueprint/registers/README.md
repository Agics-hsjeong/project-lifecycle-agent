# 원장 작성법

빈 원장은 실제 자료를 읽은 뒤 채운다. 예시 행을 실적처럼 포함하지 않는다. 플러그인 에이전트는 apply/review로 원장을 관리한다. 사용자가 CSV를 직접 편집할 필요는 없다. 여러 참조는 `;`로 구분한다.

- requirements.csv: REQ-ID, 원문 근거, 수용기준, 우선순위, 범위 상태, 설계·구현·테스트 파일, DEL-ID, 제외 사유.
- deliverables.csv: DEL-ID, 단계, 문서명, 파일, 담당자, 버전, 상태, REQ-ID, 적용 제외 사유. 기본 행은 전부 미승인 초안이다.
- tasks.csv: TASK-ID, REQ-ID, 역할, 담당자, 상태, 우선순위, 기한, 다음 행동, 증거 파일.
- risks.csv: RISK-ID, 영향, 가능성, 책임자, 대응, 상태.
- reviews.csv: 단계 검토 결정과 근거. 검토 일시는 `2026-10-15T14:30:00+09:00`처럼 시간대를 포함한다. 기록은 인증·전자서명 기능이 아니다.
- DECISIONS.md: ADR/CR 결정과 승인 근거. 원래 요구사항을 몰래 수정하지 않는다.

경로는 프로젝트 루트 기준 로컬 파일이며 `../`로 프로젝트 밖을 참조하지 않는다. 외부 산출물은 로컬 명세에 외부 위치와 버전을 기록한다. 원장에 비밀번호·API 키를 넣지 않는다.

state/의 이력·검토 스냅샷·복구 기록은 관리 엔진이 생성한다. 단계는 advance/rewind로 변경한다. 원장·state를 수동 변경해 검토를 우회하지 않는다. 스냅샷은 전자서명이 아니며 검토자 인증을 제공하지 않는다.
