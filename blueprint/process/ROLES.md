# 역할별 작업 계약

공통 입력: project.json, HANDOFF.md, RULES, 현재 단계 문서와 관련 원장. 공통 출력: 산출물 파일, 변경 원장, 완료·미완료·증거·다음 작업. 역할은 논리적 작업 모드이며 특정 모델에 고정하지 않는다.

| 역할 | 주요 책임 | 대표 출력 | 넘겨줄 조건 |
| --- | --- | --- | --- |
| PM·프로세스 관리자 | 현재 단계·범위·일정·리스크·의존성 확인, 질문과 판단 요청 정리 | 착수 계획·작업 원장·인수인계 | 다음 역할의 입력·ID·수용기준 명확 |
| 사업·제안 분석가 | RFP/가설·평가기준 분석, EVAL→제안서 절 연결, 정성제안 전략·주장·증거, 공수 산정 근거 | 검토서·정성제안서·평가 대응표·산정서 | 지정 목차·평가항목 대응과 근거·가정·제외 구분 |
| 제안 발표·문서 제작자 | 제안서 제출본 제작, 발표 스토리·시각 구성·슬라이드·시간 배분, 대본·예상 질의, 문서/발표 정합성·시각 검수 | DOCX/HWP/PDF·PPTX/PDF·대본/Q&A·제출 점검표 | 실제 파일 생성·렌더링, EVAL↔SLIDE 추적, 제출 조건·발표 시간 확인 |
| 서비스 기획자 | 사용자 여정·업무 정책·화면·수용기준 | 기획 명세·요구 원장 | 기능·예외·권한·상태 추적 가능 |
| 설계자 | 아키텍처·API·데이터·보안·비기능 설계 | 기술 설계·ADR | 기술 선택 이유·검증 방법 명확 |
| 디자이너 | 정보 계층·토큰·화면·상태·반응형 기준 | 디자인 명세·버전 링크 | 구현에 필요한 상태와 자산 확인 |
| 퍼블리셔 | HTML/CSS/컴포넌트·반응형·접근성 구현 | UI·점검 기록 | 디자인 대응·상태·환경 증거 확보 |
| 개발자 | 기능·API·데이터 구현, 단위/통합 검증 | 코드·리뷰·구현 기록 | REQ 추적·테스트 근거·미해결 이슈 기록 |
| QA·리뷰어 | 수용기준·회귀·권한·실패 시나리오 검증 | 결과·결함·검수 대응 | 재현 가능한 결과와 잔여 위험 정리 |
| 배포·운영 담당 | 릴리스·관측·복구·운영 인수 | 릴리스·운영 매뉴얼 | 부여된 권한·실행 결과·운영 책임 명확 |
| 유지보수 담당 | 장애·변경 영향 분석, 수정·회귀·정기 점검 | INC/CR·유지보수 기록 | 지원 범위·릴리스·재발 방지 연결 |

## 역할 전환 요청

```text
[역할]로 작업해줘. 현재 단계와 관련 요구사항 ID부터 확인해줘.
입력 자료의 근거를 확인하고 관련 산출물 초안을 작성해줘.
불확실한 사항은 가정과 질문으로 구분하고,
원장과 HANDOFF.md에 결과·증거·다음 역할의 입력을 남겨줘.
```

같은 AI가 작성과 검토 역할을 맡을 수 있지만 독립된 사람의 승인으로 표현하지 않는다. 중요한 인수·배포 판단은 실제 책임자가 근거를 확인한다.
