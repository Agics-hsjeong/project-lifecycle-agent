# 공통 업무 규칙

## 사실과 근거

분석 문장과 요구사항에 원본 파일·페이지·절 또는 확인 가능한 출처를 붙인다. 추정 공수·비용·일정에는 가정과 산정 방식을 적는다. 고객 실적·인증·법적 적합성·성과 수치를 만들어내지 않는다. 충돌하는 입력은 차이와 영향, 결정할 책임자를 기록한다.

## 범위와 의사결정

최종 계약·수용기준 또는 승인된 MVP를 범위 기준으로 삼는다. 제안서가 자동으로 계약 기준이 되는 것은 아니다. 추가 요구는 CR로 일정·비용·설계·테스트·운영 영향을 분석하고 승인된 변경만 기준선에 반영한다.

검토/승인 기록은 registers/reviews.csv에 남긴다. AI가 사람 이름으로 자기 결과를 승인하지 않는다. 사용자 결정이나 기존 승인 문서를 근거로 옮겨 적을 때는 근거 경로를 함께 기록한다. 실제 권한 통제는 별도 시스템에서 시행한다.

## 상태와 ID

- 요구사항 상태: proposed → baselined → implemented → verified → accepted. 제외는 deferred와 사유로 기록한다.
- 산출물 상태: draft → in_review → approved. 적용 제외는 not_applicable과 사유·검토 기록을 남긴다.
- 작업 상태: todo / doing / blocked / done. 담당자·다음 행동·관련 REQ를 적는다.
- 검토 결정: approved / rejected. stage는 WORKFLOW에 정한 영문 코드다.
- CSV는 UTF-8로 저장하고 여러 ID·로컬 파일 경로는 `;`로 구분한다. 경로는 프로젝트 루트 기준이며 실제 파일을 가리킨다.
- 검토 근거가 바뀌면 원장의 승인 상태를 in_review로 되돌리고 재검토한다. 과거 기록은 삭제하지 않는다.

플러그인으로 운영할 때 원장은 apply, 실제 결정은 review, 단계 변경은 advance/rewind로 기록한다. 엔진은 검토 시점의 범위·입력·문서·근거를 비교하며 바뀐 검토로 단계 이동하지 않는다. 각 검토의 근거는 별도 파일로 보존한다. HANDOFF에는 완료·미실행·미결정·다음 행동을 남긴다. 잠금·복구 기록은 직접 삭제하지 않고 recover로 확인한다.

## 구현과 품질

기존 스택·스타일·구조를 따르고 새로운 기술 선택은 ADR에 이유와 영향을 남긴다. 구현 작업에는 요구사항 ID와 수용기준이 있어야 한다. 변경의 위험에 맞는 테스트를 실행하고 환경·명령·결과를 기록한다.

UI는 정상·로딩·빈 화면·오류·권한 없음 상태를 명세한다. 반응형·키보드 접근·레이블·대비를 프로젝트 수용기준에 맞춰 점검한다. 수치 기준은 실제 적용 표준과 계약을 확인해 정한다.

테스트용 데이터와 운영 데이터를 구분하고 입력 검증·접근권한·개인정보 처리를 확인한다. CI가 없으면 검증 기록을 남기되 자동 검증이 있다고 보고하지 않는다.

## 버전과 납품

코드가 있는 프로젝트는 TASK/REQ를 포함한 작은 변경 단위로 작업한다. 기본 브랜치 직접 변경, 강제 푸시, 커밋 삭제는 저장소 정책과 사용자 권한을 따른다. 브랜치 예: feature/TASK-001-status-page, fix/INC-001-access.

릴리스는 버전·커밋·변경 목록·테스트·배포·복구 절차를 묶는다. v0.1.0처럼 버전을 쓰되 계약이나 조직의 규칙이 있으면 그것을 따른다. 실제 커밋·태그 없이 버전만으로 코드가 보존되었다고 주장하지 않는다.

산출물에는 ID·담당자·버전·상태·관련 요구사항을 붙인다. 외부 Figma나 문서 링크는 버전/노드/조회일을 로컬 명세에 남긴다. 납품은 코드·문서·라이선스·운영 매뉴얼·계정 이전·인수 결과를 목록과 대조한다.

## 운영과 유지보수

개발·검증·운영 환경을 구분하고 자격증명은 별도 비밀정보 저장소에서 관리한다. 운영 배포·데이터 변경·복구는 부여된 권한과 실행 절차에 따른다. 권한이 필요한 경우 먼저 변경 내용·검증·복구 방법을 준비한다.

유지보수는 INC/CR ID로 추적한다. 대응 시간·지원 시간·하자 보수·유상 변경 구분은 실제 합의에서 가져온다. 임의로 24시간 지원이나 SLA를 약속하지 않는다. 긴급 대응 권한이 사전 부여됐다면 그 범위에서 대응하고 증거와 후속 검토를 남긴다.
